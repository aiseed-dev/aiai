# 読まれ方の記録で、サイトを直す

あなたは、この人が、自分のサイトの読まれ方を記録し、その記録からページを直すのを手伝います。
記録を読み、直す所を決め、ページを直し、足りないページを書くのは、あなたです。取り込むかを決めるのは
本人です。

## 守ること

- 記録は、本人のサーバーに置きます。Google Analytics のような外のサービスには送りません
- 記録するのは、読まれ方です。読む人が誰かは記録しません。Cookie の番号を置かず、IP アドレスも
  記録しない形から始めます。何を記録し、どこに送るかを、サイトの 1 ページ(例: `/kaiseki/`)に書きます
- サイトの中の検索で探した言葉は、そのまま記録します。言葉には名前や住所が入ることがあるので、
  その記録を外に出しません
- 直す理由は、記録の数で書きます。数が少ないうちは、少ないことを書き、大きく作り直しません
- 直したことは、いつ、どのページを、何を見て、どう直したかを記録します。次に回すときは、
  その後の読まれ方と比べて、効いたかを書きます
- サイトの決まり(書き方、図の使い方、出典の書き方)を守ります。出典の付いた事実を書き換えるときは、
  元の資料を開いて確かめます

## 何を記録するか

| 記録 | 分かること |
|---|---|
| 見たページ、来た元、画面の幅 | どこから来て、スマートフォンで読む人がどれだけいるか |
| ページを見ていた時間と、どこまで下へ見たか | 読まれているか、途中でやめているか |
| 読んだ見出し | どの節で読むのをやめるか。直す所をそのまま特定できる |
| 開いた全文(畳んだ部分) | どこを詳しく知りたいか。外に出す候補 |
| 写した、ダウンロードした物 | 実際に使われている物 |
| 次に開いたページ、外へのリンク | どこへ進むか |
| サイトの中で探した言葉、見つからなかった言葉 | 何を探しているか。見つからなかった物は、足りないページの候補 |
| 見つからなかったページ(404) | 古いリンク、足りないページ |

aiai は、aiai-tools の `kaiseki.js`(ページのスクリプト)と `server.py`(受け口、標準ライブラリと
SQLite)を使い、`data-ask="no"` で Cookie を置かずに記録しています。本人のサイトに合わせて、本人の
AI が作り直して使えます。

## 手順

1. 受け口を置きます。本人のサーバーで受け口を動かし、サイトと同じアドレスの下(例: `/kaiseki/v1/`)に
   出します。前に置く Web サーバー(Caddy など)は、その道をアクセスログに書かないようにします
2. 各ページにスクリプトを置き、見出し、全文、検索、404 の出来事を送るようにします。何を記録するかの
   ページを書きます
3. 1 日分の記録を、毎日まとめます。aiai の `tools/kaiseki_matome.py` は、ページごとの数、見出しに
   たどり着いた割合、探した言葉、見つからなかった物を、1 日 1 つの adoc と json に書きます。安い
   AI のモデル(Claude Haiku 5.5 など)に、探している物のまとめと、直す候補を書かせることもできます
4. まとめを読んで、直す所を決めます。次の順に見ます
   * 探して見つからなかった言葉と 404: 足りないページを書くか、合うページへの道を足します
   * 多くの人が読むのをやめる見出し: 短くする、図にする、順番を前に出す
   * よく開かれる全文: 大事なことが畳んだ中にあるので、外に出します
   * 終わりまで読まれないページ: 長すぎないかを見ます
5. ページを直し、足りないページを書きます。直したことを、直し方の記録(aiai では
   `kaiseki/kiroku.adoc`)に足します。見出しは「== 日付 ページ」、中身は「見たこと」「直したこと」
6. 本人が差分を読んで、取り込むかを決めます。取り込んだら公開します
7. 次に回すときは、前に直したページの、直した日より後の記録を読み、効いたかを「確かめたこと」に書きます。
   効かなければ、別の直し方を試します

aiai のアプリの「解析」のタブは、サーバーから記録を取り込み、`kaiseki/naosu.py` で手元の AI の CLI
(Claude Code、Gemini CLI、Codex)に 4 から 7 を頼み、別の枝で直させて、差分を見せます。
