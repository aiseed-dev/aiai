= kaiseki ユーザーマニュアル
:日付: 2026-10-12
:対象: サイトを運営する人と、サイトを読む人

設計は `sekkei.adoc` にあります。ここでは、使う手順だけを書きます。

== 1. サイトを運営する人

=== 1.1 見られる物

kaiseki で見られるのは、次の物です。

* ページごとの表示回数、見ていた時間、どこまで下へ見たか
* 来た元(リンク元のホスト、utm)と、スマートフォンの割合
* サイトの中で探した言葉、見つからなかった言葉、見つからなかったページ(出来事を入れたサイトのみ)

Google Analytics にある、地域、年齢、性別の推定、広告の成果は、見られません。IP アドレスを記録しないためです。

=== 1.2 毎日のまとめを読む

前の日(日本時間)のまとめが、1 日 1 つのファイルになります。

[cols="1,3"]
|===
| ファイル | 中身

| `YYYY-MM-DD.adoc` | 人が読む形。表示、ページ、読んだ見出し、探した言葉、AI の所見
| `YYYY-MM-DD.json` | 同じ内容を機械が読む形
|===

aiai.aiseed.dev では、VM の `~/aiai-server/kaiseki/` に毎日 0 時 10 分に書かれます。手元の PC では、
aiai のアプリの「解析」のタブで取り込めます。

weather.time-j.net のまとめは、2026-10-12 時点ではまだ作っていません。deb2 の受け口を替えた後、
次の手順で作れるようにします(`sekkei.adoc` の 8 章)。

=== 1.3 1 日分を手で作る

受け口の DB があるサーバーで、次を動かします。`--day` を省くと昨日です。`--out` を省くと、画面に出すだけです。

[source,bash]
----
python3 tools/kaiseki_matome.py --db <kaiseki.db のパス> --site weather.time-j.net --suspect-screen 1920x1080 --day 2026-10-12
----

AI の所見も付けるときは `--out <フォルダー> --ai gemini` を足します。Google Cloud のサービスアカウントが要るので、
Google Cloud の VM でだけ動きます。

=== 1.4 サイトに入れる

. 受け口を動かします。`KAISEKI_SITES` に、受けるサイトのホストを入れます
. 前の Web サーバー(Caddy など)で、受け口の道をアクセスログに書かないようにします
. 各ページの `</head>` の前に、スクリプトを置きます(`sekkei.adoc` の 4.1)
. 同意を聞くときは、`/kaiseki/` のページに、送る情報、送り先、目的、選び直し方を書きます。聞かないときは
  `data-ask="no"` にします
. 開いて、受け口の DB に表示が入ったかを確かめます

=== 1.5 出来事を足す

ページの動きに合わせて、次のように書きます。

[source,javascript]
----
kaiseki.event("search", { value: "札幌" });
----

名前は英小文字、数字、`_` で 40 字までです。値は 100 字までの短い言葉にします。氏名、住所、電話などの
識別情報が入らないことを、足す前に確かめます。毎日のまとめに出すには、`tools/kaiseki_matome.py` で数える
名前に足します。

=== 1.6 手元で試す

受け口を自分の PC で動かし、サイトを手元で作って確かめます(weather の `docs/operations.md` に手順があります)。
受け口の確かめは次のとおりです。

[source,bash]
----
python3 kaiseki/test_server.py
----

=== 1.7 止める

ページのスクリプトを外します。weather では、deb2 の `~/.config/weather-site/kaiseki.env` を消すと、次の生成から
スクリプトと `/kaiseki/` が消えます。受け口の記録は、そのままです。消すときは、DB を直接直します。

=== 1.8 受け口を替える

. `data/kaiseki.db` を `cp` で控えます
. `server.py` を上書きします
. 受け口を再起動します(deb2 では `sudo systemctl restart kaiseki`)
. 起動時に、`scroll` と `value` の列が古い DB に足されます。サイトを開いて、表示が入ることを確かめます

=== 1.9 毎日のまとめを自動で動かす(2 か所とも同じ形)

受け口のサーバーごとに、systemd の service と timer を置きます。違うのは、DB の場所、サイトのホスト、
`--ai gemini` を付けるかだけです。`--ai gemini` は Google Cloud のサービスアカウントで動くので、
aiai の VM だけに付けます。deb2 では付けず、まとめ(`.adoc`)を本人の AI に読ませます。

[cols="1,2,2"]
|===
| | aiai の VM(Google Cloud) | deb2

| 置く場所 | `~/aiai/` | `~/kaiseki/`(`tools/kaiseki_matome.py` と `tools/kougeki.py` を写す)
| DB | `~/aiai-server/kaiseki/kaiseki.db` | `/home/dev/kaiseki/data/kaiseki.db`
| サイト | `aiai.aiseed.dev` | `weather.time-j.net`
| 書く先 | `~/aiai-server/kaiseki` | `/home/dev/kaiseki/matome`
| AI の所見 | `--ai gemini` | 付けない
|===

[source,ini]
----
# /etc/systemd/system/kaiseki-matome.service (deb2 の例)
[Unit]
Description=kaiseki: sum up yesterday

[Service]
Type=oneshot
User=dev
ExecStart=/usr/bin/python3 /home/dev/kaiseki/tools/kaiseki_matome.py --db /home/dev/kaiseki/data/kaiseki.db --site weather.time-j.net --suspect-screen 1920x1080 --out /home/dev/kaiseki/matome

# /etc/systemd/system/kaiseki-matome.timer
[Unit]
Description=kaiseki: sum up yesterday, daily

[Timer]
OnCalendar=*-*-* 00:10:00 Asia/Tokyo
Persistent=true

[Install]
WantedBy=timers.target
----

置いたら `sudo systemctl enable --now kaiseki-matome.timer` で始め、`systemctl list-timers` で次の時刻を確かめます。

== 2. サイトを読む人

同意を聞くサイト(weather.time-j.net)では、初めて開くと、画面の下に帯が出ます。

[cols="1,3"]
|===
| 選ぶ物 | 起きること

| 受け入れる | このサイトの Cookie に乱数の番号を置き、見たページの記録を、その番号でまとめます。同じ運営者のほかのサイトへのリンクをたどると、番号が一緒に渡ります
| 受け入れない | 番号を置きません。ページを開いたことだけが、誰のとも分からない形で数えられます
|===

どちらの場合も、IP アドレスは記録しません。

選び直すときと、記録を見る、消すときは、サイトの `/kaiseki/` のページで行います。ブラウザーの開発者向けの画面からは、
`kaiseki.forget()` で番号と記録を消せます。
