= サーバーの攻撃の記録（kougeki）設計書
:toc:
:toc-title: 目次

== 目的と完成の基準

このアプリは、自分のサーバーが受けた攻撃を毎日数え、AI に所見を書かせて、本人が読むためのものです。
毎朝、前の日にサーバーが何を受けたかと、手を打つことがあるかを、1 つの画面で読めるようにします。
自分のサーバーを自分で持つ本人 1 人が使います。サインインはありません。

== 全体の仕組み

このアプリは、守るサーバーの上で動くプログラムと、本人の PC の aiai のアプリの 2 つで動きます。
標準ライブラリだけの Python（Python 3.11 以上）で作ります。サーバーには追加のソフトや部品を何も入れません。
無料で作って動かします。かかる費用は AI の利用料だけです。

=== サーバーですること

* 守るサーバーの上で、毎日 0 時 5 分（日本時間）に `cron`（または `systemd-timer`）を使って root 権限でプログラム（`/usr/local/bin/kougeki_count.py`）を動かします。
* プログラムは、前の日の 0 時 0 分 0 秒から 23 時 59 分 59 秒までの 24 時間の記録を読みます。
* 集計が終わったら、1 日 1 つの記録として、人が読める形（`YYYY-MM-DD.adoc`）とプログラムが読む形（`YYYY-MM-DD.json`）の 2 つのファイルを、サーバーの本人のフォルダー（`~/kougeki/`）に保存します。
* 保存したファイルの持ち主（オーナー）は、root から本人のユーザーに変えます。
* 一時ファイルは作りません。メモリーの上だけで数えます。
* 記録を外のサービスには送りません。また、ファイアウォールや Web サーバーの設定を書き換えて通信を遮断するようなことはせず、サーバーには何もしません。

=== 本人の PC ですること

* 本人の PC の aiai のアプリの「サーバー」のタブを開き、「記録を写す」ボタンを押すと、SSH（`scp`）を使ってサーバーの `~/kougeki/` から手元の PC の `~/aiai/kougeki/` へ、まだ写していない `adoc` ファイルと `json` ファイルを写します。
* サーバーが Google Cloud の外にあり、サーバー側で AI を呼べないときは、ファイルを写したあとに、手元の PC の AI（Claude Code）を呼んで所見を書かせ、手元の `adoc` ファイルと `json` ファイルに書き足します。

== 数える物と読み方

決まった 3 つの対象だけを数えます。書き方が分からない行は無視し、「未分類の記録」としては出しません。
安全のために、シェルの命令を文字列で組み立てて実行する作り方（`shell=True` など）はしません。また、記録の中の文字をそのまま正規表現の規則として使うこともしません。

=== 1. SSH でログインしようとして失敗した試み（sshd の記録）

* 読む場所: `/var/log/auth.log` または `/var/log/secure` を Python で直接開いて読みます。これらのファイルがない新しい Linux（Debian 12 など）では、`subprocess.run(["journalctl", "-u", "ssh", "-u", "sshd", "--since", "yesterday", "--until", "today", "-o", "cat"], shell=False)` を実行して読みます。
* 数える行: `Failed password` または `Invalid user` が含まれる行を数えます。
* 取り出す物: 合計の回数と、送り元の IP アドレスごとの回数を数えます。回数が多かった送り元の IP アドレスを上から 5 つまで取り出します。

=== 2. 穴を探す HTTP の要求（Web サーバーのアクセスの記録）

* 読む場所: `/var/log/nginx/access.log`、`/var/log/nginx/access.log.1`、`/var/log/apache2/access.log`、`/var/log/httpd/access_log` のうち、存在するファイルを Python で直接開いて読みます。
* 数える行: 前の日の日付の行のうち、要求された URL（パス）に次の文字が含まれるもの、または応答の状態コードが `400`、`403`、`404` のものを数えます。
** 探す文字: `/.env`、`/.git`、`wp-admin`、`wp-login.php`、`phpmyadmin`、`cgi-bin`、`../`、`/etc/passwd`
* 取り出す物: 合計の回数と、送り元の IP アドレスごとの回数を数えます。回数が多かった送り元の IP アドレスを上から 5 つまで取り出します。

=== 3. 外に開いている口（待ち受けているポート）

* 読む場所: `/proc/net/tcp`、`/proc/net/tcp6`、`/proc/net/udp`、`/proc/net/udp6` を Python で直接開いて読みます。
* 数える行: 待ち受け状態（TCP は状態が `0A`、UDP は状態が `07`）であり、待ち受けているアドレスが自分自身（`127.0.0.1`、`::1` など）ではない行を調べます。
* 取り出す物: 外に向けて開いているポート番号と通信の種類（TCP または UDP）の一覧（重複を除いたもの）を取り出します。

== AI に所見を書かせる仕組み

* **AI に渡す情報**: その日の記録（3 つの対象の数、多かった送り元の IP アドレス 5 つまで、外に開いている口の一覧）と、前の日の記録（`~/kougeki/` にある前の日の `json` ファイルから読んだ 3 つの対象の数と外に開いている口の一覧）だけを渡します。生のログの行や、サーバーの名前、設定ファイルの中身などは渡しません。
* **AI に頼むこと**: 「前の日と比べていつもと違うこと」と「本人が手を打つことがあるか」を、日本語の普通の文で、8 行以内で書くように頼みます。AI は読んで書くだけで、サーバーには何もしません。
* **AI の呼び方（Google Cloud の上の場合）**: サーバーが Google Cloud の Compute Engine の上で動いているときは、サーバーの中に API の鍵ファイルを置かずに呼びます。Python の `urllib.request` でメタデータサーバー（`http://metadata.google.internal/computeMetadata/v1/instance/service-accounts/default/token`）から一時的なトークンを取り、Vertex AI の Gemini API（`gemini-2.5-flash`）を呼んで所見を受け取ります。
* **AI の呼び方（本人の PC の場合）**: Google Cloud の外にあるサーバーでは、サーバーの上では数えるだけにして、AI の所見欄を空にしておきます。本人の PC で記録を写したときに、PC に入っている `claude` コマンド（`subprocess.run(["claude", "-p", ...], shell=False)`）を呼んで所見を作らせます。

== 記録のファイルの形

サーバーの `~/kougeki/` に、毎日 2 つのファイルを作ります。

=== プログラムが読む形（YYYY-MM-DD.json）

文字コードは UTF-8 とします。次の項目を入れます。

* `date`: 日付（`2026-10-16` の形）
* `ssh_failed`:
** `total`: 合計の回数（数値）
** `top_ips`: `[{"ip": "203.0.113.5", "count": 120}, ...]`（最大 5 つ）
* `http_probes`:
** `total`: 合計の回数（数値）
** `top_ips`: `[{"ip": "198.51.100.9", "count": 85}, ...]`（最大 5 つ）
* `open_ports`: `["22/tcp", "80/tcp", "443/tcp"]` のような文字列の並び
* `previous_day`:
** `ssh_failed_total`: 前の日の SSH 失敗の合計（前の日の記録がないときは `null`）
** `http_probes_total`: 前の日の HTTP 要求の合計（前の日の記録がないときは `null`）
** `open_ports`: 前の日の開いている口の一覧（前の日の記録がないときは `null`）
* `ai_comment`: AI が書いた 8 行以内の所見の文字列

=== 人が読める形（YYYY-MM-DD.adoc）

文字コードは UTF-8 とします。上から順に、日付の見出し、AI の所見、その日の数（前の日との差を含む）、多かった送り元の IP アドレス（5 つまで）、外に開いている口の一覧を書きます。

== 画面

画面は、本人の PC の aiai のアプリの中にある 1 つだけです。サインインの画面や、設定の画面はありません。

=== 1. 「サーバー」のタブの画面

毎朝、前の日にサーバーが何を受けたかと、手を打つことがあるかを、この 1 つの画面で読みます。上から順に次の物が並びます。

* **見出し**: 「サーバーの攻撃の記録」
* **操作の並び**:
** **入力の欄**: 「サーバーの接続先」（例: `user@example.com`。1 回入れたら手元の設定ファイル `~/aiai/kougeki/config.json` に保存し、次からは最初から入っています）
** **ボタン**: 「記録を写す」（押すと、入力された接続先の `~/kougeki/` から手元の PC へ新しい記録を SSH で写し、必要なら手元の AI で所見を書き足して、下の表示を更新します）
** **文字**: 写した日時、またはエラーの知らせ（1 行）
* **見出し**: 「日ごとの一覧」
** **選択の欄（一覧）**: 日付（`YYYY-MM-DD`）が新しい順に並びます。画面を開いたときは、一番上の最新の日（前の日）が最初から選ばれています。別の日を押すと、その日の記録が下に表示されます。
* **見出し**: 「選ばれた日の記録（YYYY-MM-DD）」
** **見出し**: 「AI の所見（いつもと違うこと・手を打つこと）」
*** **文字**: AI が書いた所見（最大 8 行）を表示します。
** **見出し**: 「受けた数と開いている口」
*** **文字**: 「SSH のログイン失敗: ○○ 件（前の日: △△ 件）」
*** **文字**: 「穴を探す HTTP の要求: ○○ 件（前の日: △△ 件）」
*** **文字**: 「外に開いている口: 22/tcp, 80/tcp, 443/tcp」
** **見出し**: 「多かった送り元の IP アドレス（5 つまで）」
*** **文字**: SSH のログイン失敗の送り元 IP アドレスと件数（最大 5 行）
*** **文字**: 穴を探す HTTP の要求の送り元 IP アドレスと件数（最大 5 行）

== 自分で決めたこと

資料の SKILL.md に書かれていない細かな点について、次のように決めました。

. **サーバーで動かす時刻**: 「毎日 0 時過ぎ（日本時間）」は、日付が変わった直後のログの切り替え（ローテーション）と重ならないように、毎日 0 時 5 分（`5 0 * * *`）に決めました。
. **記録を置く場所とファイル名**: サーバーの「本人のフォルダー」の場所は `~/kougeki/` とし、ファイル名は日付を使った `YYYY-MM-DD.adoc` と `YYYY-MM-DD.json` に決めました。手元の PC の保存先は `~/aiai/kougeki/` に決めました。
. **穴を探す HTTP の要求の見分け方**: Web サーバーの記録から穴を探す要求を数える基準として、よく狙われるパス（`/.env`、`/.git`、`wp-admin`、`wp-login.php`、`phpmyadmin`、`cgi-bin`、`../`、`/etc/passwd`）が含まれる行、またはエラーの応答（状態コード `400`、`403`、`404`）の行を数えることに決めました。
. **外に開いている口の見分け方**: 追加のコマンド（`ss` や `netstat`）がサーバーに入っていなくても確実に読めるように、Linux の `/proc/net/tcp`、`/proc/net/tcp6`、`/proc/net/udp`、`/proc/net/udp6` を Python で直接読んで、外向けの待ち受けポートを調べることに決めました。
. **systemd-journald への対応方法**: `/var/log/auth.log` や `/var/log/secure` がない環境では、利用者に設定ファイルを書き換えさせるのではなく、Python から `journalctl` を `shell=False` で呼んで読むことに決めました。
