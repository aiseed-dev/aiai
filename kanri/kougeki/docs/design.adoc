= サーバーの攻撃の記録（kougeki）設計書
:toc:
:toc-title: 目次

== 目的と完成の基準

インターネットにつないだ自分のサーバーが受けた攻撃を毎日数え、AI に所見を書かせて、本人が読むためのアプリです。
完成の基準は、毎朝、前の日にサーバーが何を受けたかと、手を打つことがあるかを、1 つの画面で読めることです。言われていないことは足しません。
使う人は自分のサーバーを自分で持つ本人 1 人で、サインインはありません。アプリ自体は無料で、かかる費用は AI の利用料だけです。

== 全体の仕組み

このアプリは、守るサーバーの上で動く「数えるプログラム」と、本人の PC の aiai のアプリの中で動く「見る画面のプログラム」の 2 つでできています。どちらも標準ライブラリだけの Python（Python 3.11 以上）で作ります。サーバーには追加のソフトや常駐プログラムを一切入れません。

* **数えるプログラム（サーバー側）**: 毎日 0 時 05 分（日本時間）に `root` の権限で動きます。前の日の 0 時 00 分 00 秒から 23 時 59 分 59 秒までの 24 時間の記録を数えます。数えた結果と AI の所見を、サーバーの中の本人のフォルダーに、人が読める形（`.adoc`）とプログラムが読む形（`.json`）の 2 つのファイルとして保存します。外のサービスには何も送りません。
* **見る画面のプログラム（本人の PC 側）**: 本人の PC の aiai アプリの「サーバー」のタブを開いたときに動きます。環境変数 `AIAI_SERVER` にサーバーの SSH 接続先が書いてある場合は、そこから記録ファイルを手元の PC に写して表示します。PC がサーバーそのものである場合は、`AIAI_SERVER` を空にし、同じ PC の中のフォルダーを直接読みます。

== 数える処理（サーバー側）

=== 動かす仕組みと場所

サーバーの `cron`（`/etc/cron.d/kougeki`）を使い、毎日日本時間の 0 時 05 分に `root` で `/usr/local/bin/kougeki_count.py` を動かします。一時ファイルは作らず、メモリの上だけで数えます。
結果を置く場所は、本人のホームフォルダーの下の `~/kougeki/` とします。ファイルを作ったあと、本人が読めるようにファイルの持ち主を本人に変えます。

=== 数える物と読み方

数える物は次の 3 つだけに絞ります。これ以外の記録は無視し、「未分類の記録」として出すことはしません。
記録を読むときは、記録の中の文字をシェルの命令として実行したり、正規表現の式として組み立てたりせず、Python の文字列処理とあらかじめ固定した正規表現だけで安全に数えます。外部の命令を呼ぶときは `subprocess.run` に配列で引数を渡し、`shell=True` は使いません。

. **SSH でログインしようとして失敗した試み（sshd の記録）**
  * `/var/log/auth.log` または `/var/log/secure` があればそれを読みます。無い場合は `journalctl -u ssh -u sshd --since YYYY-MM-DD --until YYYY-MM-DD` の出力を読みます。
  * 数える項目は、失敗した試みの数、鍵で入れた回数、パスワードでの認証が切ってあるか、多い相手（上位 5 つまでの IP アドレスと件数）、試された名前（上位 5 つまでのユーザー名と件数）です。
  * パスワードでの認証が切ってあるかは、`sshd -T` の出力、または `/etc/ssh/sshd_config`（および `/etc/ssh/sshd_config.d/` の中のファイル）を読み、`PasswordAuthentication no` になっているかで確かめます。

. **穴を探す HTTP の要求（Web サーバーのアクセスの記録）**
  * `/var/log/nginx/access.log` または `/var/log/apache2/access.log`（または `/var/log/httpd/access_log`）を読みます。前の日の分が `.1` などのファイルに分かれている場合は、それも合わせて読み、前の日の日付の行だけを数えます。Web サーバーが入っておらず記録ファイルが無い場合は、数を 0 とします。
  * 要求の全体の数と、そのうち穴を探す要求の数を数えます。
  * 穴を探す要求とは、要求された URL の道筋に `/.env`、`/.git`、`wp-admin`、`wp-login.php`、`phpmyadmin`、`/etc/passwd`、`..`、`.php`（ただし普通に公開しているページを除くため、応答の状態コードが 400、403、404 のもの）が含まれるものとします。
  * 探された所（上位 5 つまでの URL の道筋と件数）と、探してきた相手（上位 5 つまでの IP アドレスと件数）も数えます。

. **外に開いている口（待ち受けているポート）**
  * `ss -tuln` を実行して結果を読みます。
  * `127.0.0.1` や `::1` など、サーバーの中だけに向いている口は除き、`0.0.0.0` や `::` や外向けの IP アドレスで待ち受けている TCP と UDP のポート番号を並べます。

=== AI に所見を書かせる処理

AI は読んで書くだけで、サーバーの設定を変えたり通信を遮断したりすることは一切しません。
AI に渡す情報は、その日の数えた結果（それぞれの数と、多かった送り元の IP アドレス 5 つまで、試された名前や探された所 5 つまで、外に開いている口）と、前の日の同じ項目の数だけです。生のログの行や、サーバーの大切な設定の中身は渡しません。
AI には、「前の日の数と比べていつもと違うことと、本人が手を打つことがあるかを、日本語の普通の説明文で 8 行以内で書くこと」を指示します。返ってきた文章が 8 行を超えていた場合は、プログラムで先頭の 8 行だけに切り詰めます。

AI を呼ぶ方法は、次の 2 つのうちどちらかを環境に合わせて使います。どちらの場合も、サーバーの中に AI の API キー（鍵ファイル）は置きません。

* **Google Cloud の上で動かす場合**: サーバーに付いているサービスアカウントを使い、メタデータサーバー（`http://metadata.google.internal/...`）から一時的なトークンを受け取って、Vertex AI の Gemini API（`gemini-2.5-flash`）を `urllib.request` で呼びます。
* **本人の PC の AI（Claude Code）を使う場合**: サーバーの上では数える処理だけを行い、AI の所見欄は「（未作成）」としてファイルを保存します。本人の PC で「サーバーから取り込む」（または「読み直す」）ボタンを押したときに、まだ所見が「（未作成）」であれば、PC 側で `claude -p` 命令を呼んで所見を書かせ、手元の `.json` と `.adoc` を更新します。

=== 保存するファイルの形

毎日、`~/kougeki/YYYY-MM-DD.json` と `~/kougeki/YYYY-MM-DD.adoc` の 2 つを作ります。

* `YYYY-MM-DD.json` には、日付、AI の所見、SSH の集計、HTTP の集計、外に開いている口の一覧を JSON の形で入れます。画面の表示にはこのファイルを使います。
* `YYYY-MM-DD.adoc` には、同じ内容を人がそのまま読める AsciiDoc の形で入れます。画面の「コピー」ボタンを押したときは、この `.adoc` の中身をクリップボードに写します。

== 画面

見る所は、本人の PC の aiai のアプリの「サーバー」のタブです。PC の幅の画面（横幅 1024px 以上を基準）で作ります。スマートフォンの形にはしません。画面は 1 つだけです。入力の欄は置きません。

=== 1. サーバーの攻撃の記録画面（aiai の「サーバー」タブ）

画面を開いたときは、手元の PC に保存されている記録を読み込み、いちばん新しい日の記録を開いた状態で表示します。
上から順に、次の物を並べます。

. **見出し**: 「サーバーの攻撃の記録」
. **ボタン**:
  * 環境変数 `AIAI_SERVER` に接続先が設定されているときは、「サーバーから取り込む」という文字のボタンを置きます。押すと、`scp` 命令（`subprocess.run(["scp", ...])`）を使ってサーバーの `~/kougeki/` から新しい `.json` と `.adoc` を手元の PC の `~/.local/share/aiai/kougeki/` に写し、画面の表示を更新します。
  * 環境変数 `AIAI_SERVER` が空のとき（PC がサーバーそのもののとき）は、「読み直す」という文字のボタンを置きます。押すと、`~/kougeki/` のファイルを読み直して画面の表示を更新します。
  * 接続先のサーバー名などを画面で入力する欄は置きません。
. **見出し**: 「日ごと」
. **日ごとの表**:
  * 新しい日が上になるように、1 日 1 行で並べます。
  * 列は左から順に、「日」「SSH の試み」「多い相手」「HTTP の要求」「穴を探す要求」「開いている口」の 6 つです。
  * 「日」の列にある日付（例: `2026-10-16`）は押せるようになっており、押すと下の「選んだ 1 日の中身」がその日の記録に切り替わります。初めは、いちばん新しい日を開いておきます。
. **選んだ 1 日の中身**:
  * **見出し**: 「<日> の記録」（例: 「2026-10-16 の記録」）
  * **ボタン**: 「コピー」。押すと、その日の記録（`.adoc` ファイルの中身）をクリップボードに写し、ふだん使っている AI にそのまま貼れるようにします。
  * **AI の所見**: 見出し「AI の所見」の下に、8 行以内の所見の文章を表示します。
  * **SSH**: 見出し「SSH」の下に、次の項目を表示します。
    ** 失敗した試みの数
    ** 鍵で入れた回数
    ** パスワードでの認証が切ってあるか（「切ってある」または「切ってない（要注意）」）
    ** 多い相手（IP アドレスと回数を最大 5 つ）
    ** 試された名前（ユーザー名と回数を最大 5 つ）
  * **HTTP**: 見出し「HTTP」の下に、次の項目を表示します。
    ** 要求の数
    ** 穴を探す要求の数
    ** 探された所（URL の道筋と回数を最大 5 つ）
    ** 探してきた相手（IP アドレスと回数を最大 5 つ）
  * **外に開いている口**: 見出し「外に開いている口」の下に、待ち受けているポート番号と種類の並び（例: `22/tcp, 80/tcp, 443/tcp`）を表示します。

== 自分で決めたこと

資料の SKILL.md に書かれていない細かい点について、次のように決めました。

. **毎日の集計を動かす時刻**: SKILL.md の「毎日 0 時過ぎ(日本時間)」に従い、日替わりのログの切り替え（logrotate）と重ならないよう、毎日 0 時 05 分（日本時間）に `cron` で動かすことに決めました。
. **ファイルを置く場所と名前**: サーバーの上では本人のホームフォルダーの下の `~/kougeki/` に `YYYY-MM-DD.json` と `YYYY-MM-DD.adoc` という名前で置くことに決めました。本人の PC で外から取り込む場合は、`~/.local/share/aiai/kougeki/` に写して保存することに決めました。
. **上位の件数の上限**: 画面の「多い相手」「試された名前」「探された所」「探してきた相手」に出す件数は、AI に渡す IP アドレスの数に合わせて、それぞれ上位 5 つまでと決めました。日ごとの表の「多い相手」の列には、1 番多かった相手の IP アドレス（1 つ）と件数を出すことに決めました。
. **穴を探す HTTP の要求の見分け方**: Web サーバーの記録のうち、よく狙われるパス（`/.env`、`/.git`、`wp-admin`、`wp-login.php`、`phpmyadmin`、`/etc/passwd`、`..`）を含む要求、および存在しない `.php` ファイルへの要求（状態コードが 400、403、404 のもの）を「穴を探す要求」として数えることに決めました。
. **AI の呼び方の切り替え**: サーバーが Google Cloud の Compute Engine であるかどうかをメタデータサーバーへの通信で確かめ、Google Cloud なら鍵を置かずに Vertex AI の Gemini（`gemini-2.5-flash`）を呼び、そうでないなら本人の PC で取り込んだときに PC 側の Claude Code（`claude -p`）を呼ぶ仕組みに決めました。

== 今あるアプリの課題を防ぐ対応表

資料 `references/kougeki-analysis.adoc` に挙げられている問題点を、この設計書のどこで防いでいるかを示します。

[cols="1,2,2", options="header"]
|===
| 防ぐこと（資料の項目） | 今あるアプリの問題点 | この設計書での防ぎ方

| 1. 高い料金や、分かりにくい追加の費用がかかること
| Google Cloud Security Command Center は年間最低 15,000 米ドルや従量課金、ログ保存の間接費用がかかります。CrowdSec も AI 機能や長期保存には月額 29 ドルからの有料プランが必要です。
| 「目的と完成の基準」および「全体の仕組み」のとおり、標準ライブラリだけの Python で作り、手元のファイルに保存するため、アプリの料金は無料で、かかる費用は AI の利用料だけになります。

| 2. 報告が長くなりすぎたり、問題のない通知が多くて見分けにくくなったりすること
| Security Command Center はノイズの整理が必要で、Logwatch は未分類の記録（Unmatched Entries）が大量に並んで報告が長くなります。
| 「数える物と読み方」のとおり、数える物を 3 つだけに絞り、それ以外の行は無視して未分類の記録を出しません。また「AI に所見を書かせる処理」のとおり、所見を 8 行以内に制限します。

| 3. サーバーの記録や大切な情報を外のサービスに送って集めたり、AI にログをそのまま渡したりすること
| Security Command Center や CrowdSec は記録や IP アドレスを運営会社に集めます。また、生のログをそのまま AI に渡すと大切な情報が漏れる危険があります。
| 「全体の仕組み」と「AI に所見を書かせる処理」のとおり、記録はサーバーの本人のフォルダーに置き、外のサービスには送りません。AI に渡すのも、集計した数と上位 5 つまでの IP アドレスや名前だけに絞ります。

| 4. 外の画面にアカウントを作ってサインインさせたり、運営側の都合で機能や契約を変えられたりすること
| Security Command Center は段階の廃止などがあり、CrowdSec は外の管理画面にアカウント登録とサインインが必要で、運営側にアカウントを停止されることがあります。
| 「目的と完成の基準」と「画面」のとおり、本人 1 人が使うアプリでサインインはありません。本人の PC の aiai の「サーバー」タブの 1 画面だけで見られます。

| 5. サーバーに専用の常駐プログラムやメール送信ソフトなどの部品を追加で入れること
| Logwatch は Postfix などのメール送信ソフトが必要でメール不達の問題があり、CrowdSec は専用の常駐プログラムやデータベースを入れる必要があります。
| 「全体の仕組み」と「画面」のとおり、標準ライブラリだけの Python で作り、サーバーには何も足しません。メールは使わず、PC から `scp` で取り込んで画面で見ます。

| 6. 記録の絞り込みや新しい記録の仕組みへの対応で、難しい設定の手直しや一時ファイルの削除が必要になること
| Logwatch は正規表現や Perl の書き換え、`/var/cache/logwatch` の一時ファイル削除、`systemd-journald` への対応設定に手間がかかります。
| 「動かす仕組みと場所」と「数える物と読み方」のとおり、一時ファイルは作らず、文字の記録ファイルと `journalctl` の両方に初めから対応し、決まった 3 つだけを数えるため、利用者の設定の手直しは不要です。

| 7. プログラムが読める形（JSON）で記録を出せないこと
| Logwatch は JSON や XML で結果を出す機能が断られており、プログラムから読みにくい問題があります。
| 「保存するファイルの形」のとおり、毎日、人が読める形（`.adoc`）とプログラムが読む形（`.json`）の両方を本人のフォルダーに保存します。

| 8. 記録の文字やファイル名からプログラムが異常終了したり、外の命令を実行されたりすること
| Logwatch には、記録の文字列で異常終了する弱点（CVE-2005-1061）や、ファイル名からシェルの命令を実行される弱点（CVE-2011-1018）がありました。
| 「数える物と読み方」のとおり、記録の文字から正規表現を組み立てず、外部命令を呼ぶときも `shell=True` を使わずに配列で引数を渡すことで、異常終了や命令の実行を防ぎます。

| 9. 通信の遮断など、サーバーの動きに自動で手を加えること
| CrowdSec はファイアウォールや Web サーバーと連携して通信の遮断などを自動で行います。
| 「全体の仕組み」と「AI に所見を書かせる処理」のとおり、プログラムは記録を読んで数えるだけで、AI も読んで書くだけとし、サーバーには何もしません。

| 10. サーバーの中に AI を呼ぶための鍵ファイルを置くこと
| Security Command Center の鍵管理の手間や、CrowdSec で開発者の端末からトークンが盗まれた事故のように、鍵を置くことによる漏えいの危険があります。
| 「AI に所見を書かせる処理」のとおり、サーバーには API キーを置かず、Google Cloud のメタデータサーバーによる認証を使うか、本人の PC 側の AI（Claude Code）を使います。
|===
