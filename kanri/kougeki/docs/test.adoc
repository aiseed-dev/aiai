== マニュアルの操作の確かめ

利用者マニュアルに出てくる操作を、順番に確かめます。

[cols="1,2,3,3,1", options="header"]
|===
| 番号 | 画面 | すること | そうなるはずのこと | 確かめ

| 1
| サーバーの攻撃の記録画面（aiai の「サーバー」タブ）
| 別の場所にあるサーバーの記録を見るとき、設定（`AIAI_SERVER`）にサーバーの SSH の接続先を書いて、PC で aiai のアプリを開き、「サーバー」のタブを選びます。
| サインインはなく、画面の上にある「サーバーから取り込む」ボタンが表示されます。
| 

| 2
| サーバーの攻撃の記録画面（aiai の「サーバー」タブ）
| お使いの PC がサーバーそのものであるとき、設定（`AIAI_SERVER`）を空にして、PC で aiai のアプリを開き、「サーバー」のタブを選びます。
| サインインはなく、画面の上にある「読み直す」ボタンが表示されます。
| 

| 3
| サーバーの攻撃の記録画面（aiai の「サーバー」タブ）
| 画面の上にある「サーバーから取り込む」ボタンを押します（お使いの PC がサーバーそのものであるときは、「読み直す」ボタンを押します）。
| 「日ごと」の表がいちばん新しい状態になり、初めはいちばん新しい日の記録が下に開きます。
| 

| 4
| サーバーの攻撃の記録画面（aiai の「サーバー」タブ）
| 「日ごと」の表を見ます。
| 新しい日が上になるように毎日の数が並んでおり、表の列が左から「日」「SSH の試み」「多い相手」「HTTP の要求」「穴を探す要求」「開いている口」になっています。
| 

| 5
| サーバーの攻撃の記録画面（aiai の「サーバー」タブ）
| 下に開いた「<日> の記録」の中身を見ます。
| 「AI の所見」（8 行以内）、「SSH」（失敗した試みの数、鍵で入れた回数、パスワードでの認証が切ってあるか、多い相手、試された名前）、「HTTP」（要求の数、穴を探す要求の数、探された所、探してきた相手）、「外に開いている口」（待ち受けているポートの番号と種類）が出ています。
| 

| 6
| サーバーの攻撃の記録画面（aiai の「サーバー」タブ）
| 「日ごと」の表の「日」の列にある、別の日の日付を押します。
| 押した日の記録が下の「<日> の記録」に開きます。
| 

| 7
| サーバーの攻撃の記録画面（aiai の「サーバー」タブ）
| 「<日> の記録」の見出しの近くにある「コピー」ボタンを押します。
| その日の記録が写され、ふだんの AI の画面にそのまま貼り付けることができます。
| 
|===

== 問題点が起きないことの確かめ

設計書の「今あるアプリの課題を防ぐ対応表」の行ごとに、問題点が起きないことを確かめます。

. **1. 高い料金や、分かりにくい追加の費用がかかること**
  * サーバーのプログラムと画面のプログラムを標準ライブラリだけの Python（Python 3.11 以上）で動かし、記録を手元のフォルダー（`~/kougeki/` または `~/.local/share/aiai/kougeki/`）に保存して、外の有料サービスにつながずに AI の呼び出しだけで動くことを確かめます。

. **2. 報告が長くなりすぎたり、問題のない通知が多くて見分けにくくなったりすること**
  * 数えるプログラムを動かして作られた記録や画面の「<日> の記録」を見て、SSH、HTTP、外に開いている口の 3 つだけが出力され、未分類の記録が出ていないことと、「AI の所見」が 8 行以内におさまっていることを確かめます。

. **3. サーバーの記録や大切な情報を外のサービスに送って集めたり、AI にログをそのまま渡したりすること**
  * 数えるプログラムを動かしたとき、記録ファイルがサーバーの本人のフォルダー（`~/kougeki/`）にだけ保存され、AI に渡す内容がその日の数えた結果（数と、上位 5 つまでの IP アドレスや名前・道筋、外に開いている口）と前の日の数だけであり、生のログの行や設定の中身が含まれていないことを確かめます。

. **4. 外の画面にアカウントを作ってサインインさせたり、運営側の都合で機能や契約を変えられたりすること**
  * 手元の PC で aiai のアプリの「サーバー」タブを開いたとき、アカウントの登録やサインインの画面が出ずに、1 つの画面だけで記録が読めることを確かめます。

. **5. サーバーに専用の常駐プログラムやメール送信ソフトなどの部品を追加で入れること**
  * サーバーにメール送信ソフトや常駐プログラムを入れない状態で、cron から数えるプログラムが動き、PC 側の画面で「サーバーから取り込む」ボタンを押すと `scp` でファイルが写されて画面に表示されることを確かめます。

. **6. 記録の絞り込みや新しい記録の仕組みへの対応で、難しい設定の手直しや一時ファイルの削除が必要になること**
  * `/var/log/auth.log`（または `/var/log/secure`）がある環境と、`journalctl` を使う環境のどちらでも、設定を手直しせずに SSH の記録が数えられ、実行後に一時ファイルが残らないことを確かめます。

. **7. プログラムが読める形（JSON）で記録を出せないこと**
  * 数えるプログラムを動かしたあと、`~/kougeki/` の中に `YYYY-MM-DD.adoc` と `YYYY-MM-DD.json` の 2 つのファイルが作られ、`.json` ファイルが JSON として読み込めることを確かめます。

. **8. 記録の文字やファイル名からプログラムが異常終了したり、外の命令を実行されたりすること**
  * 記録の中に正規表現の記号やシェルの特殊文字が含まれるテスト用のログを読ませたとき、プログラムが異常終了せず、シェルの命令としても実行されずに数えられることを確かめます。

. **9. 通信の遮断など、サーバーの動きに自動で手を加えること**
  * 数えるプログラムと AI に所見を書かせる処理を動かした前後で、サーバーのファイアウォールや Web サーバーなどの設定が一切変わっていないことを確かめます。

. **10. サーバーの中に AI を呼ぶための鍵ファイルを置くこと**
  * サーバーの中に AI の API キーのファイルを置かない状態で、Google Cloud の上ではメタデータサーバーからトークンを受け取って Gemini API を呼び、そうでない環境では所見を「（未作成）」として保存し PC 側で取り込んだときに `claude -p` を呼んで所見が書かれることを確かめます。

== 試験に書くこと

本人の AI が自動の試験に書く項目の一覧です。

* SSH の記録（`/var/log/auth.log`、`/var/log/secure`、または `journalctl` の出力）から、前の日の 0 時 00 分 00 秒から 23 時 59 分 59 秒までの失敗した試みの数、鍵で入れた回数、多い相手（上位 5 つまで）、試された名前（上位 5 つまで）が正しく数えられること。
* `sshd -T` の出力または `/etc/ssh/sshd_config`（および `/etc/ssh/sshd_config.d/`）から、`PasswordAuthentication no` かどうかを読み取り、パスワードでの認証が切ってあるかを正しく判定できること。
* Web サーバーの記録（`.1` などのファイルを含む）から、前の日の日付の行だけを数え、要求の全体の数、穴を探す要求（`/.env`、`/.git`、`wp-admin`、`wp-login.php`、`phpmyadmin`、`/etc/passwd`、`..`、および状態コードが 400、403、404 の `.php`）の数、探された所（上位 5 つまで）、探してきた相手（上位 5 つまで）が正しく数えられること。記録ファイルが無い場合は数が 0 になること。
* `ss -tuln` の出力から、`127.0.0.1` や `::1` などの内向けの口を除き、外向けの TCP と UDP のポート番号の並びが正しく取り出せること。
* 記録の中に正規表現の特殊文字やシェルの命令のような文字列が入っていても、異常終了や命令の実行が起きずに安全に処理されること。
* AI に渡す情報に生のログの行が含まれず、集計した数と上位 5 つまでの項目と前の日の数だけが渡されること。
* AI から返ってきた所見の文章が 8 行を超えていた場合、先頭の 8 行だけに切り詰められること。
* 集計結果と所見が、`YYYY-MM-DD.json` と `YYYY-MM-DD.adoc` の 2 つのファイルとして正しい形で保存されること。
* 画面を開いたとき、保存されている記録のうちいちばん新しい日の記録が開いた状態で表示され、日ごとの表が新しい日を上にして並ぶこと。
* 環境変数 `AIAI_SERVER` の有無によって、ボタンの表示と動作が「サーバーから取り込む」と「読み直す」に切り替わること。
* 所見が「（未作成）」の記録を PC 側で取り込んだ（または読み直した）とき、`claude -p` を呼んで `.json` と `.adoc` の所見が更新されること。
* 日ごとの表の日付を押すと、下の「<日> の記録」がその日の内容に切り替わること。
* 「コピー」ボタンを押すと、その日の `.adoc` ファイルの中身がクリップボードに写されること。
