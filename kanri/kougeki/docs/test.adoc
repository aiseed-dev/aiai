== マニュアルの操作の確かめ

利用者マニュアルに書かれている操作を、上から順に確かめます。

[cols="1,2,3,3,1", options="header"]
|===
| 番号 | 画面 | すること | そうなるはずのこと | 確かめ

| 1
| 「サーバー」のタブの画面
| パソコンで aiai のアプリを開き、「サーバー」のタブを選びます。
| サインインなしで、「サーバー」のタブの画面が開きます。
| 

| 2
| 「サーバー」のタブの画面
| 初めて使うときに、「サーバーの接続先」の欄に自分のサーバーの接続先（例: `user@example.com`）を入れます。
| 入力した接続先が欄に入り、2 回目からは最初から入っています。
| 

| 3
| 「サーバー」のタブの画面
| 「記録を写す」ボタンを押します。
| ボタンの横に写した日時が出て、最新の記録が画面に並びます。
| 

| 4
| 「サーバー」のタブの画面
| 「日ごとの一覧」と、その下の表示を見ます。
| 一番上の新しい日（前の日）が最初から選ばれています。その下に「AI の所見（いつもと違うこと・手を打つこと）」（8 行以内）、「受けた数と開いている口」（「SSH のログイン失敗」の件数と前の日の件数、「穴を探す HTTP の要求」の件数と前の日の件数、「外に開いている口」の一覧）、「多かった送り元の IP アドレス（5 つまで）」が並んでいます。
| 

| 5
| 「サーバー」のタブの画面
| 「日ごとの一覧」から、前の日よりも前の読みたい日付を押します。
| 押した日の記録が下に表示されます。
| 
|===

== 問題点が起きないことの確かめ

設計書の「== 課題（問題点）をどこで防いでいるかの表」の行ごとに、問題が起きないことを確かめます。

. **高い料金や、分かりにくい追加の費用がかかること**
* 確かめ方: サーバーのプログラム（`/usr/local/bin/kougeki_count.py`）と手元の PC のアプリが標準ライブラリだけの Python（Python 3.11 以上）で作られており、有料の監視サービスや追加の検査機能を使っておらず、かかる費用が AI の利用料だけであることを確かめます。

. **報告が長くなりすぎたり、問題のない通知が多くて見分けにくくなったりすること**
* 確かめ方: 書き方が分からない行を含むログを読ませたときに、「未分類の記録」が出ずに 3 つの対象（SSH のログイン失敗、穴を探す HTTP の要求、外に開いている口）だけが数えられること、および「サーバー」のタブの画面で AI の所見が 8 行以内で表示されることを確かめます。

. **サーバーの記録や大切な情報を外のサービスに送って集めたり、AI にログをそのまま渡したりすること**
* 確かめ方: 集計した記録がサーバーの `~/kougeki/` に保存されて外のサービスには送られないこと、および AI に渡す情報がその日の記録（3 つの対象の数、多かった送り元の IP アドレス 5 つまで、外に開いている口の一覧）と前の日の記録（3 つの対象の数と外に開いている口の一覧）だけであり、生のログの行やサーバーの名前、設定ファイルの中身を渡していないことを確かめます。

. **外の画面にアカウントを作ってサインインさせたり、運営側の都合で機能や契約を変えられたりすること**
* 確かめ方: 外のサービスへのアカウント登録やサインインの画面がなく、手元の PC の aiai のアプリの「サーバー」のタブの画面 1 つだけで記録を読めることを確かめます。

. **サーバーに専用の常駐プログラムやメール送信ソフトなどの部品を追加で入れること**
* 確かめ方: サーバーに常駐プログラムやメール送信ソフトを入れず、`cron`（または `systemd-timer`）で 1 日 1 回動く Python プログラムだけで記録が作られ、「サーバー」のタブの画面の「記録を写す」ボタンから SSH（`scp`）で手元の PC の `~/aiai/kougeki/` に写して読めることを確かめます。

. **記録の絞り込みや新しい記録の仕組みへの対応で、難しい設定の手直しや一時ファイルの削除が必要になること**
* 確かめ方: プログラムを動かしたときに一時ファイルが作られずメモリーの上だけで数えること、および `/var/log/auth.log` や `/var/log/secure` がない環境では利用者が設定を手直ししなくても自動で `journalctl` を実行して SSH の記録を読むことを確かめます。

. **プログラムが読める形（JSON）で記録を出せないこと**
* 確かめ方: サーバーの `~/kougeki/` に、人が読める形（`YYYY-MM-DD.adoc`）とプログラムが読む形（`YYYY-MM-DD.json`）の 2 つのファイルが UTF-8 で作られ、持ち主（オーナー）が本人のユーザーになっていることを確かめます。

. **記録の文字やファイル名からプログラムが異常終了したり、外の命令を実行されたりすること**
* 確かめ方: プログラムの中で `shell=True` を使っておらず（`journalctl` や `claude` や `scp` を呼ぶときは `shell=False` にしていること）、記録の中の文字やシェルの特殊文字を含む行を読ませても、それを正規表現の規則やシェルの命令として使わずに安全に数えられることを確かめます。

. **通信の遮断など、サーバーの動きに自動で手を加えること**
* 確かめ方: サーバーのプログラムと AI の呼び出しを動かしたあと、ファイアウォールや Web サーバーの設定が書き換えられておらず、サーバーには何もしていないことを確かめます。

. **サーバーの中に AI を呼ぶための鍵ファイルを置くこと**
* 確かめ方: サーバーの中に AI の API の鍵ファイルを置いていないことを確かめます。Google Cloud の Compute Engine の上ではメタデータサーバーから一時的なトークンを取って Vertex AI の Gemini API（`gemini-2.5-flash`）を呼ぶこと、Google Cloud の外ではサーバー側で AI の所見欄を空にし、手元の PC で「記録を写す」ボタンを押したときに PC の `claude` コマンドを呼んで所見を書き足すことを確かめます。

== 試験に書くこと

本人の AI が自動の試験に書く項目の一覧です。

* **SSH のログイン失敗の集計**: `/var/log/auth.log` または `/var/log/secure`（ファイルがないときは `journalctl` の出力）から、前の日の 0 時 0 分 0 秒から 23 時 59 分 59 秒までの `Failed password` または `Invalid user` を含む行だけを数え、合計の回数と、回数が多かった送り元の IP アドレスを上から 5 つまで取り出せること。
* **穴を探す HTTP の要求の集計**: Web サーバーのアクセスの記録から、前の日の日付の行のうち、指定された 8 つの文字（`/.env`、`/.git`、`wp-admin`、`wp-login.php`、`phpmyadmin`、`cgi-bin`、`../`、`/etc/passwd`）が URL に含まれる行、または状態コードが `400`、`403`、`404` の行だけを数え、合計の回数と、回数が多かった送り元の IP アドレスを上から 5 つまで取り出せること。
* **外に開いている口の集計**: `/proc/net/tcp`、`/proc/net/tcp6`、`/proc/net/udp`、`/proc/net/udp6` から、待ち受け状態（TCP は `0A`、UDP は `07`）で自分自身（`127.0.0.1`、`::1` など）ではない行を調べ、ポート番号と通信の種類（`22/tcp` など）の重複のない一覧を取り出せること。
* **未分類の行と危険な文字の扱い**: 書き方が分からない行は無視して数えないこと。また、記録の中に正規表現の記号やシェルの特殊文字が入っていても異常終了せず、外の命令が実行されないこと（`shell=True` を使っていないこと）。
* **前の日の記録との比較とファイルの保存**: 前の日の `YYYY-MM-DD.json` があるときは前の日の数と開いている口を読み取り、ないときは `null` にして、当日の `YYYY-MM-DD.json` と `YYYY-MM-DD.adoc` を UTF-8 で出力し、一時ファイルを作らないこと。
* **AI に渡す情報と文字数の制限**: AI に渡すデータに生のログの行が含まれず、集計した数と上位 5 つまでの IP アドレスと開いている口の一覧（当日と前日分）だけが含まれること。また、受け取った所見が 8 行以内におさまること。
* **手元の PC での設定保存と記録の写し**: 「サーバーの接続先」が `~/aiai/kougeki/config.json` に保存されて次に開いたときに読み込まれること。「記録を写す」の実行でまだ写していない `adoc` と `json` が `~/aiai/kougeki/` に写され、AI の所見が空のときは `claude` コマンド（`shell=False`）で所見が `adoc` と `json` に書き足されること。
* **画面の表示と日付の切り替え**: `~/aiai/kougeki/` にある記録の日付が「日ごとの一覧」に新しい順で並び、最初は一番上の新しい日が選ばれて表示され、別の日を選ぶとその日の記録に表示が切り替わること。
