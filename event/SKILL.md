# 静的サイトと Flet のフォームへの作り直し

PHP や WordPress で動いているサイトを、PHP を使わない形に作り直します。コードはあなた(AI)が書きます。本人は動きを確かめ、
直したい所をあなたに伝えます。本人は HTML も JavaScript も知らない前提で進めます。

元にする考え方: 動く部分を減らせば、守る部分も減ります。サイトは静的なファイルだけにし、PHP もデータベースも置きません。
問い合わせのフォームは、誰でも送れる「認証の無い口」なので、来た物は全部疑い、量を絞ります。

## やること

目標の 1 つめは、2 の段の静的なサイトの公開です。公開できたら、目標 1 を達成したと本人に伝えます。目標の 2 つめは、3〜6 の段の
問い合わせのフォームの作成です。

段ごとに、何を作るかを先に 2〜3 行で本人に伝え、作り、本人に確かめてもらってから次の段に進みます。コマンドは 1 つずつ示し、
何が起きるかを 1 行添えます。本人が見た物(画面、エラーの文)を伝えてきたら、それを元に直します。

1. 載せる中身を決めます
   - 今のサイトがある場合: 緊急なので、今のサイトの棚卸しはしません。本人に今のサイトの URL か、ページの文章を出してもらい、
     トップページと、トップページからリンクしているお知らせのページ(あれば)の 2 つに載っている中身(文章、画像、リンク)を
     取り出して、ページごとに一覧にまとめます。今のサイトに書いていない事実は足しません
   - 新しく作る場合: 本人に聞かずに、本人が書いた中身で、すぐにお知らせのページを作ります(1 と 2 の段を続けてする)。空いている所は
     「(ここに〇〇を書く)」の形で空けておき、本人が書いていない事実は足しません。直すのは、本人が後でします
2. ページを作り、Cloudflare Pages に上げます。今のサイトがある場合は、1 の段の一覧からトップページとお知らせのページ(あれば)を作り、
   トップページからお知らせのページへリンクします。本人がブラウザーで開いて確かめます
3. 受け口の Worker と R2 のバケットを上げます
4. 問い合わせのフォームを Flet で作り、`flet build web` で書き出して、静的なサイトと一緒にもう一度上げます
5. 担当者のアプリを Flet で作ります
6. 本人が自分のフォームから 1 件送り、担当者のアプリで受け取り、R2 から消えたことを確かめます

## 決まっていること

### 置き場所

本人の PC に作業のフォルダーを 1 つ作り、その中に置きます。

- `public/`: Pages に上げる物(静的なサイト。フォームを書き出した物は `public/toiawase/`)
- `toiawase/`: フォームの Flet のアプリ(`main.py`)
- `worker/`: 受け口(`worker.js` と `wrangler.toml`)
- `uketori/`: 担当者のアプリ(`main.py`)

Python の部品(`flet`、`cf-publish`)は、作業のフォルダーの仮想環境に入れます。

### 静的なサイト

- HTML と CSS だけで書きます。JavaScript は使いません。今のサイトの文章と画像だけを使い、PHP のファイルは 1 つも持ってきません
- 作るページは、今のサイトがあればトップページと、トップページからリンクしているお知らせのページ(あれば)。新しく作るなら
  お知らせのページです
- 問い合わせのフォームへのリンク(`/toiawase/`)を置きます
- 見本で作るときは、架空の会社にし、架空と書きます

### 問い合わせのフォーム

- 上から、見出し「お問い合わせ」、「お名前」(50 文字まで)、「メールアドレス」(254 文字まで)、「お問い合わせの内容」(数行、
  2000 文字まで)、送る前の説明、ボタン「送る」、結果を並べます
- 送る前の説明には、送った内容を Cloudflare に置き、担当者が受け取ったら消すことを書きます
- 送っている間はボタンを押せなくし、受け付けたら入力を消して「受け付けました」と出します。受け付けなかったときは、Worker が返した
  理由をそのまま出します
- 送り先の Worker の URL は、`main.py` の先頭の定数 `WORKER_URL` に書きます
- 書き出した物はブラウザーの中の Python(Pyodide)で動くので、送るときは `pyodide.http.pyfetch` を使います。`urllib` や
  `requests` は使いません
- 書き出しは `flet build web --base-url toiawase`(`toiawase/` の中で動かす)です。できた `toiawase/build/web` の中身を
  `public/toiawase/` に写します。初めての `flet build web` は Flutter SDK を自動で入れるので、時間がかかります

### 受け口の Worker

口は次の 4 つだけにします。

| 口 | 誰が | すること |
|---|---|---|
| `POST /toiawase`(と、送る前の問い合わせの `OPTIONS`) | フォーム | 確かめて、通れば R2 に 1 件置く |
| `GET /uketori` | 担当者のアプリ | `toiawase/` の下に置いてある物の一覧(`kazu/` の印は返さない) |
| `GET /uketori/<名前>` | 担当者のアプリ | 1 件を読む |
| `DELETE /uketori/<名前>` | 担当者のアプリ | 1 件を消す |

`POST /toiawase` では、次をすべて確かめ、1 つでも通らなければ置きません。理由は、フォームにそのまま出せる日本語で返します。

- 送り元(`Origin`)が、静的なサイトの URL(`SITE_ORIGIN`)と同じ。`Origin` が無い物も受け取らない
- 形が JSON で、本文が 10,000 文字まで
- 項目は `namae`、`mail`、`naiyou` の 3 つだけで、どれも文字。長さは決まりの中。改行とタブのほかの制御文字は捨てる
- お名前と内容が空でなく、メールアドレスの形をしている
- 内容の中のリンクが 2 つまで
- 同じ 1 分(日本時間)に受けた数が `MAX_PER_MINUTE`(既定 5)より少ない。ボットがまとめて送る物を止めるための上限です
- その日(日本時間)に受けた数が `MAX_PER_DAY`(既定 500)より少ない。ふだんの問い合わせでは届かない、上の守りです
- 数えるのは、R2 の `kazu/<日本時間の日付>/<時分>/` に置いた印の数。受け付けるたびに、中身の無い印を 1 つ置く。1 分の数はその分の
  フォルダー、1 日の数はその日のフォルダーで数える。印には識別情報を入れず、担当者のアプリでは消さない(問い合わせの方は受け取ると
  消えるので、それを数えると、受け取るたびに枠が空いてしまう)。2 つの数は、AI が案を出し、本人と決める

送り元が合っているときは、受け付けない返事(400、413、415、429)にも `Access-Control-Allow-Origin` を付けます。付けないと、ブラウザーが
返事を捨て、フォームに理由が出ません。

置くのは、書かれた 3 項目と受け付けた時刻だけです。IP アドレスとブラウザーの種類は置きません。名前は
`toiawase/<日本時間の日付>/<時刻>-<乱数>.json` にします。

担当者の口は、`Authorization: Bearer <STAFF_TOKEN>` が合うときだけ答えます。`STAFF_TOKEN` が設定されていないときも閉じます。
比べ方は、かかる時間が中身で変わらない比べ方にします。`/uketori/<名前>` の名前は、上の形に合う物だけを受けます。

`wrangler.toml` には、`name`、`main`、`compatibility_date`、R2 のバインディング(`TOIAWASE`、バケット `toiawase`)、
`[vars]` の `SITE_ORIGIN`、`MAX_PER_MINUTE`、`MAX_PER_DAY` を書きます。npm の部品は使いません(cf-publish はまとめる道具を持たないため)。

上限は、送られる量を絞るだけです。多数の送り元から集中して送られると、上限で断っていても Worker は呼ばれ続け、問い合わせも
受けられなくなります。そのときは、まず受け口を止めます(`cf-publish worker deploy worker --no-workers-dev` で Worker の URL を閉じ、
サイトのフォームへのリンクを外して上げ直す)。最後の守りは認証(Apple ID と Google ID で、送る人を確かめてから受ける)です。この手引きでは
作りません。

Worker を上げる前に、R2 を手元の偽物にした試験を書いて、上の確かめを 1 つずつ試します。Node.js があれば `node` で動かします。

### 担当者のアプリ

- Flet のデスクトップのアプリで、`flet run uketori/main.py` で動かします
- 送り先と鍵は、`~/.config/toiawase.env` の `TOIAWASE_URL` と `TOIAWASE_TOKEN` から読みます。画面に入れる欄は置きません
- ボタン「受け取る」で、置いてある物を 1 件ずつ読み、`~/toiawase/` に JSON で保存し、保存できた物だけを R2 から消します。
  保存に失敗した物は消しません
- 保存した物を新しい順に並べ、受け付けた時刻(日本時間に直す)、お名前、メールアドレス、内容を見せます
- Worker を呼ぶときは、アプリの名前を `User-Agent` に付けます(例: `toiawase-uketori/1.0`)。Python の `urllib` が既定で名乗る
  `Python-urllib/3.x` は、Cloudflare に「error code: 1010」(403)で断られます

問い合わせには、お名前とメールアドレスが入ります。Cloudflare には長く置かず、受け取ったら消します。

### 公開(cf-publish)

Cloudflare には cf-publish(https://github.com/aiseed-dev/cf-publish)で上げます。wrangler と Node.js は使いません。

| 上げる物 | コマンド |
|---|---|
| 静的なサイトとフォーム | `cf-publish public --project <プロジェクト名>` |
| Worker と R2 のバケット | `cf-publish worker deploy worker --secret STAFF_TOKEN --workers-dev` |

- API トークンの権限は、目標 1 には「Cloudflare Pages: 編集」だけで足ります。目標 2 の前に「Workers Scripts: 編集」と
  「Workers R2 Storage: 編集」を足します。
  トークンとアカウントの ID は、本人が `~/.config/cloudflare/pages.env` に `CLOUDFLARE_API_TOKEN=` と
  `CLOUDFLARE_ACCOUNT_ID=` の形で書きます
- `STAFF_TOKEN` は、本人が `python -c "import secrets; print(secrets.token_urlsafe(32))"` で作り、`~/.config/toiawase.env` と、
  上げるときの環境の変数にだけ置きます
- R2 のバケットは、無ければ `worker deploy` が作ります。その前に、本人がダッシュボードで R2 を使い始める手続き(支払いの方法の登録を
  求められる)を済ませておく必要があります。済んでいないと言われたら、参加者のページの「Cloudflare の設定を足す」を見てもらいます
- Pages の URL は `https://<プロジェクト名>.pages.dev` です。cf-publish が上げるたびに出す `https://<8 桁>.<プロジェクト名>.pages.dev` は、
  その回だけの URL で、上げた直後は開けないことがあります。`SITE_ORIGIN` には、決まった方の URL を書きます
- Worker の URL は、`--workers-dev` を付けたときに出ます。サブドメインが無いと言われたときは、本人に
  ダッシュボードの「Workers & Pages」を開き、「Your subdomain」を見てもらいます
- 順番: Pages を上げる → `https://<プロジェクト名>.pages.dev` を `SITE_ORIGIN` に書く → Worker を上げて URL を知る → `WORKER_URL` に書いて書き出す →
  Pages をもう一度上げる

### 秘密の値

API トークン、アカウントの ID、`STAFF_TOKEN` は、本人がファイルに書きます。チャットに貼ってもらいません。コードと、作業の
フォルダーに置くほかのファイルにも書きません。もし貼られたら、そのトークンを無効にして作り直すよう伝えます。

### 失う物と代わりの手段

| 失う物 | 代わりの手段 |
|---|---|
| 問い合わせのフォーム | この手引きのフォーム。R2 に支払いの方法を登録したくないときと、小さい所は、Google フォームへのリンクでもよい(3〜5 の段は要らない) |
| 会員のログイン | Apple と Google の認証を使う。この手引きでは作らない |
| コメント | 外のコメントのサービス |
| サイトの中の検索 | JavaScript の簡単な検索か、外のサービス |
| 決済 | 外の決済のサービスへのリンク |
| 管理画面での投稿 | 手元で文章を書き、AI に HTML にさせて、上げる |

## 確かめ方

- 静的なサイト: Pages の URL をブラウザーで開き、ページとリンクがすべて開くか
- Worker: R2 を偽物にした試験が、すべて通るか
- フォーム: 自分のフォームから送って「受け付けました」が出るか。空のお名前、形の違うメールアドレス、リンクが 3 つの内容を送ると、
  理由が出て受け付けないか
- 担当者のアプリ: 「受け取る」で送った物が出て、`~/toiawase/` に保存され、もう一度押しても同じ物が出ないか(R2 から消えたか)
- 古いサイト: PHP と管理画面を公開したままにしていないか。古い URL から新しい URL へ移す設定(Pages の `_redirects`)が要るか

## 本人が決めること

- サイトに載せる文章
- Pages のプロジェクトの名前(URL の一部になる)
- 1 分と 1 日に受ける問い合わせの数(`MAX_PER_MINUTE`、`MAX_PER_DAY`)
- 受け取った問い合わせを、どこにどれだけ置くか
