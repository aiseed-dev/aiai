= 設計書: 静的サイトと Flet のフォームへの作り直し(勉強会)
:日付: 2026-10-25

== 1. 何のための物か

2026-10-25(日)20:00〜21:00 に、オンライン(Google Meet)で勉強会「PHP緊急脆弱性対応:静的サイト+Fletフォームへの作り直し勉強会」を開きます
(https://connpass.com/event/410690/、2026-10-25 に確かめた)。

10 月 21 日に、PHP の緊急の脆弱性(CVE-2026-109618、CVE-2026-109619)が公開されました。修正版は 8.5.12、8.4.27、8.3.36、
8.2.35 です(同じ connpass のページによる)。修正版に上げられないサイトは、止めるか作り直すしかありません。

参加者は、自分の Cloudflare のアカウントに、PHP を使わない形でお知らせのページと問い合わせのフォームを作り、問い合わせを 1 件
受け取るところまで進めます。コードは参加者の Claude が書きます。参加者は動きを確かめ、直したい所を Claude に伝えます。

この勉強会で教えるのは、コードの書き方ではなく、AI への頼み方と、できた物の確かめ方です。

== 2. 考え方

元にするのは、資料「既存の Web サイトを静的ファイルにする」です。

* 動く部分を減らせば、守る部分も減ります。サイトは静的なファイルにし、PHP もデータベースも置きません
* 入力を受ける所は、認証のある口と認証の無い口に分けます。問い合わせのフォームは、誰でも送れる「認証の無い口」です。来た物は全部疑い、
  量を絞ります
* AI が書き、点検します。人にしかできないのは、今のサイトで何が来て、誰が受け取っているかを聞いて回ることです

== 3. 全体の形

[source]
----
読む人のブラウザー
  │  お知らせのページと、フォーム(Flet を flet build web で書き出した物)を読む
  ▼
Cloudflare Pages(静的なファイルだけ)        … cf-publish で上げる
  │  フォームが、書かれた 3 項目を JSON で送る
  ▼
Cloudflare Worker                             … cf-publish worker deploy で上げる
  │  送り元、形、長さ、リンクの数、1 日の件数を確かめ、通った物だけを置く
  ▼
R2 のバケット(受け取るまでの間だけ置く)
  ▲
  │  鍵(STAFF_TOKEN)を付けて、一覧、読む、消す
担当者の PC の Flet のアプリ  →  PC のフォルダーに保存してから、R2 から消す
----

外のサービスは Cloudflare だけです。cf-publish は Python 製で、Node.js と wrangler が要りません。

== 4. 置く物

[cols="1,3"]
|===
| ファイル | 中身

| `event/SKILL.md` | 参加者が自分の Claude に渡す手引き。作る物の決まり(画面、Worker の口と確かめ、置く物と置かない物、鍵、公開の
  コマンド、秘密の値の扱い)と、段ごとのやること、確かめ方、本人が決めること。サイトでは `/event/SKILL.md` にそのまま出し、
  Claude Code が読みに行けるようにする
| `event/index.html` | 参加者のページ(`/event/`)。始まる前の準備と、段ごとに「Claude に頼む文」(コピーのボタン付き)と
  「確かめること」、頼み方の決まり。`site/make_site.py` がサイトの枠に入れ、手引きの全文をコピー用に添える
| `event/docs/design.adoc` | この設計書
|===

見本のコードは置きません。参加者の Claude が、手引きから作ります。

== 5. 段の分け方

手引きの「やること」と、参加者のページの段を同じ番号にします。参加者は「手引きの 3 の段です」と頼み、Claude は手引きの同じ段を読みます。

[cols="1,3,3"]
|===
| 段 | 参加者が Claude に渡す物 | 参加者が確かめること

| 0 | 手引き。PC の種類 | `flet` と `cf-publish` が動く。トークンのファイルが作業のフォルダーの外にある
| 1 | 今のサイトの URL(か、見本で進めると言う) | ページの抜け。フォームで何が来て、誰が受け取っているか(人が書き足す)
| 2 | Pages のプロジェクトの名前 | Pages の URL でページとリンクが開く
| 3 | Pages の URL | 試験がすべて通る。Worker の URL が出る
| 4 | Worker の URL | フォームから送って受け付けられる。空の名前、形の違うメールアドレス、リンク 3 つは理由が出て断られる
| 5 | なし | 受け取って保存され、もう一度押しても増えない
| 6 | 確かめた結果 | 古いサーバーの PHP と管理画面を公開したままにしていない
|===

== 6. 秘密の値

API トークン、アカウントの ID、`STAFF_TOKEN` は、参加者が自分でファイルに書き、Claude のチャットに貼りません。手引きは、Claude に
「貼ってもらわない。貼られたら無効にして作り直すよう伝える」と指示します。参加者のページにも同じことを書きます。

== 8. 確かめたことと、まだ確かめていないこと

* Flet 1.0.4 の Web アプリ(`flet publish` で書き出した物)から `pyodide.http.pyfetch` で POST すると、ブラウザーが送る前の問い合わせ
  (CORS)をし、`Origin` を付けて JSON を送り、手元の受け口が受け取った(2026-10-25)。`flet build web` で書き出した物では、まだ試していない
* 手引きの Worker の確かめ(送り元、形、長さ、リンクの数、1 日の件数、担当者の鍵)は、同じ決まりで書いた Worker と、R2 を偽物にした
  8 件の試験で、Node.js 24.19.0 で通った(2026-10-25)。その Worker は、見本のコードを置かないと決めたので消した
* `flet build web` は、Flutter SDK が無いと、入れるかを聞いてから自動で入れる(flet_cli 1.0.4 の `flutter_base.py`)。版は Flutter 3.44.8
* cf-publish の `worker deploy` は、README に「実物の Cloudflare アカウントに対してまだ 1 度も走らせていない」とある(0.3.1)。
  勉強会の前に、実物で通す必要がある
* Cloudflare の API トークンの権限の名前と、workers.dev のサブドメインと R2 を初めて使うときの操作は、ダッシュボードで確かめていない
