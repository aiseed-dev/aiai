= 設計書: 静的サイトと Flet のフォームへの作り直し(勉強会)
:日付: 2026-10-25

== 1. 何のための物か

2026-10-25(日)20:00〜21:00 に、オンライン(Google Meet)で勉強会「PHP緊急脆弱性対応:静的サイト+Fletフォームへの作り直し勉強会」を開きます
(https://connpass.com/event/410690/、2026-10-25 に確かめた)。

10 月 21 日に、PHP の緊急の脆弱性(CVE-2026-109618、CVE-2026-109619)が公開されました。修正版は 8.5.12、8.4.27、8.3.36、
8.2.35 です(同じ connpass のページによる)。修正版に上げられないサイトは、止めるか作り直すしかありません。

目標の 1 つめは、参加者が自分の Cloudflare のアカウントに、PHP を使わない静的なサイトを公開することです。目標の 2 つめは、問い合わせの
フォーム(受け口と担当者のアプリを含む)の作成です(2026-10-25 に発注者が決めた)。コードは参加者の Claude が書きます。参加者は動きを確かめ、直したい所を Claude に伝えます。

この勉強会で教えるのは、コードの書き方ではなく、AI への頼み方と、できた物の確かめ方です。

== 2. 考え方

元にするのは、資料「既存の Web サイトを静的ファイルにする」(`event/static-site.pdf`、サイトの `/event/static-site.pdf`)です。

* 動く部分を減らせば、守る部分も減ります。サイトは静的なファイルにし、PHP もデータベースも置きません
* 入力を受ける所は、認証のある口と認証の無い口に分けます。問い合わせのフォームは、誰でも送れる「認証の無い口」です。来た物は全部疑い、
  量を絞ります。多数の送り元からの集中した送りには、受け口を止めて対応し、最後の守りは認証です(今回は作らない)
* WordPress と同じように、中身とページの形を分けます。中身は Markdown(`content/`)で書き、Python のプログラム(`build.py`)が
  HTML を作ります。直すときもお知らせを足すときも、Markdown のファイルだけを触れば済みます(2026-10-25 に発注者が決めた)
* AI が書き、点検します。人にしかできないのは、今のサイトで何が来て、誰が受け取っているかを聞いて回ることです。この勉強会では、
  緊急なので棚卸しはせず、トップページとお知らせ(一覧のページと一つ一つのお知らせのページを一連で)だけを作り直します

== 3. 全体の形

[source]
----
読む人のブラウザー
  │  静的なサイトと、フォーム(Flet を flet build web で書き出した物)を読む
  ▼
Cloudflare Pages(静的なファイルだけ)        … cf-publish で上げる
  │  フォームが、書かれた 3 項目を JSON で送る
  ▼
Cloudflare Worker                             … cf-publish worker deploy で上げる
  │  送り元、形、長さ、リンクの数、1 日の件数を確かめ、通った物だけを置く
  ▼
R2 のバケット(受け取るまでの間だけ置く)
  ▲
  │  鍵(STAFF_TOKEN)を付けて、一覧、読む、消す
担当者の PC の Flet のアプリ  →  PC のフォルダーに保存してから、R2 から消す
----

外のサービスは Cloudflare だけです。cf-publish は Python 製で、Node.js と wrangler が要りません。

== 4. 置く物

[cols="1,3"]
|===
| ファイル | 中身

| `event/SKILL.md` | 参加者が自分の Claude に渡す手引き。作る物の決まり(画面、Worker の口と確かめ、置く物と置かない物、鍵、公開の
  コマンド、秘密の値の扱い)と、段ごとのやること、確かめ方、本人が決めること。Claude Code でもチャットでも、参加者のページの
  「手引きをコピー」で写して貼る。サイトの `/event/SKILL.md` にもそのまま出す
| `event/index.html` | 参加者のページ(`/event/`)。事前の準備(connpass の案内と同じ)、当日最初にする Cloudflare の設定と、段ごとに Claude に渡すプロンプト(コピーのボタン付き。1 の段は、今のサイトがある場合と新しく作る場合の 2 つ)と
  「確かめること」、頼み方の決まり。`site/make_site.py` がサイトの枠に入れ、手引きの全文をコピー用に添える
| `event/docs/design.adoc` | この設計書
|===

見本のコードは置きません。参加者の Claude が、手引きから作ります。設計書は作らせません(手引きの「決まっていること」がその役をする)。
毎日使う担当者のアプリには、短い利用者マニュアルを作らせます(2026-10-25 に発注者が決めた)。

== 5. 段の分け方

手引きの「やること」と、参加者のページの段を同じ番号にします。目標 1 は、先に HTML を作って手元のブラウザーで見えるようにし、
それから Cloudflare の設定をして上げる順にします(2026-10-25 に発注者が決めた)。参加者は「手引きの 3 の段です」と頼み、Claude は手引きの同じ段を読みます。

[cols="1,3,3"]
|===
| 段 | 参加者が Claude に渡す物 | 参加者が確かめること

| 0 | 手引き(コピーして貼る)。PC の種類。Claude Code は作業のフォルダー(例: `static-site`)で開く | なし
| 1 | 今のサイトの URL(載せる中身だけを取り出し、`content/` の Markdown にする。お知らせは一覧と一つ一つを一連で。緊急なので棚卸しはしない)か、新しく作るなら書ける所だけ書いた中身(Claude は聞かずにすぐに作り、空いた所は後で本人が直す) | 載せたい中身の抜けと古い中身。お知らせの件数が今のサイトと合うか。Claude が足した事実が無いか
| 2 | なし(新しく作る場合、1 の段でここまで進む) | `build.py` で作ったページを `python -m http.server` で開き、ページとリンクが開く。幅を狭くしても崩れない。お知らせの Markdown を 1 つ足すと、トップページと一覧に出る
| 3 | Cloudflare の設定(アカウントの ID と API トークンは参加者がダッシュボードで用意し、チャットには貼らない)。Pages のプロジェクトの名前(Claude が案を出す) | `cf-publish` が動く。トークンのファイルが作業のフォルダーの外にある。Pages の URL で、手元と同じページが開く
| デザインを考える | 目標 1 の後。Claude が業種に合う案を 3 つ(目立たせる物、色、字体)出し、参加者が選ぶか組み合わせる | パソコンとスマートフォンで、選んだ案になっていて崩れていない
| 4 | Pages の URL。1 分と 1 日に受ける数(AI が案を出して一緒に決める) | 試験がすべて通る。Worker の URL が出る
| 5 | Worker の URL | フォームから送って受け付けられる。空の名前、形の違うメールアドレス、リンク 3 つは理由が出て断られる
| 6 | 保存先(AI が案を出して一緒に決める) | 利用者マニュアルのとおりに使える。受け取って保存され、もう一度押しても増えない
| 7 | 確かめた結果 | 古いサーバーの PHP と管理画面を公開したままにしていない
|===

== 6. 秘密の値

API トークン、アカウントの ID、`STAFF_TOKEN` は、参加者が自分でファイルに書き、Claude のチャットに貼りません。手引きは、Claude に
「貼ってもらわない。貼られたら無効にして作り直すよう伝える」と指示します。参加者のページにも同じことを書きます。

== 8. 確かめたこと

2026-10-25 に、発注者の Cloudflare のアカウントで、手引きのとおりに 0〜6 の段を通しました(段の番号は、そのときの物。いまの 3 と 4〜7 にあたる)。参加者の Claude の代わりに、aiai の管理者
(Claude Code)が手引きを読んで作り、確かめました。使った版は、flet 1.0.4(Flutter 3.44.8)、cf-publish 0.3.1、Node.js 24.19.0 です。

[cols="1,4"]
|===
| 段 | 結果

| 2 | Pages のプロジェクト「aiai-event-test」ができ、`https://aiai-event-test.pages.dev` でページが開いた
| 3 | R2 を偽物にした試験 8 件が通った。`cf-publish worker deploy` が Worker「toiawase」を上げ、R2 のバケット「toiawase」を作り、
  `https://toiawase.<サブドメイン>.workers.dev` を出した。外から試すと、送る前の問い合わせは 204、`Origin` の無い送りとよそのサイトからの送りは
  403、鍵の無い担当者の口は 401、鍵のある一覧は 200 だった
| 4 | `flet build web --base-url toiawase` は 40 秒ほどで終わり、書き出した物は 13 MB だった。フォームから、空のお名前と、`@` の無い
  メールアドレスは、Worker の理由が画面に出て断られた。正しい内容は「受け付けました」が出て、入力が消えた。リンク 3 つは 400 で断られた
| 5 | 担当者のアプリが受け取り、`~/toiawase/` に保存し、R2 から消した。もう一度押すと 0 件だった
|===

通して分かり、手引きと参加者のページに足したこと:

* cf-publish が上げるたびに出す `https://<8 桁>.<プロジェクト名>.pages.dev` は、その回だけの URL で、上げた直後は開けなかった。
  `SITE_ORIGIN` には `https://<プロジェクト名>.pages.dev` を書く
* Python の `urllib` の既定の `User-Agent`(`Python-urllib/3.13`)で Worker を呼ぶと、Cloudflare が「error code: 1010」(403)で断った。
  アプリの名前を `User-Agent` に付けると通った
* Worker が置く受け付けの時刻は UTC なので、担当者のアプリでは日本時間に直して見せる
* 手引きを読んだ人の意見で、2 つを直した(2026-10-25)。上限は、問い合わせの数ではなく `kazu/<日付>/<時分>/` の印の数で数える
  (問い合わせは受け取ると消えるので、受け取るたびに枠が空いていた)。断る返事にも `Access-Control-Allow-Origin` を付ける。
  直した形で Worker を書き、R2 を偽物にした試験 10 件(受け取って消した後も上限が効くこと、断る返事に許可の頭があることを含む)が通った
* 新しく作る場合を別の Claude(Opus)が手引きどおりに作った意見で、6 つを足した(2026-10-25): 最初のページは `public/index.html`、
  2 の段では `public/toiawase/index.html` に「準備中」を置く、空けるのは本人が空欄にした所だけ、チャットで作った物は本人が
  ダウンロードして `public` に置く、プロジェクトの名前は Claude が案を入れたコマンドを出す、スマートフォンの幅でも確かめる
* 発注者の指示で、ボット対策を 1 分ごとの上限(既定 5 件)にし、1 日の上限は 500 件に上げた(1 日 50 件では、ふだんの使い方で止まる)。
  試験 11 件が通った

まだ確かめていないこと: Cloudflare のダッシュボードの画面の名前(API トークン、アカウントの ID、R2 の手続き、workers.dev の
サブドメイン)は、Cloudflare の公式の資料で確かめた(2026-10-25)が、初めて使う人のアカウントの画面では試していない(発注者の
アカウントでは、どれも前から使えた)。Windows と Mac での `flet build web`。

== 9. 次回の予定

問い合わせの中身は識別情報(お名前、メールアドレスなど)なので、Cloudflare に長く置かず、社内のサーバーに移します。次回は、フォームを
受け取る社内のサーバーを Debian で作ります。
