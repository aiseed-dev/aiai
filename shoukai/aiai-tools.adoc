= aiai tools
:lang: ja

aiai tools は、会社や団体の IT を、OSS と AI で自分の側に置くためのスキルを集めたリポジトリです。
aiai で、自分の AI と一緒に自分のアプリや Web を作れるようになった人が、会社や団体の仕事も
受けるときに使います。

リポジトリ: https://github.com/aiseed-dev/aiai-tools (2026-10-14 に確かめました)

== aiai tools とは

aiai は、個人と小さな店のための物です。aiai tools は、会社や団体のための物です。会社は、認証、
コード、文書、メール、会議、API、社内の AI、データ分析、ERP を、外のサービスに預けていることが
多くあります。aiai tools のスキルは、それを 1 つずつ、OSS と AI で自分の側に置く手順を書いて
います。

スキルは `SKILL.md` というファイルです。何を入れるか、何を守るか、どう確かめるかを書いています。
AI がスキルを読み、その会社に合わせて設定とコードを下書きします。コマンドは会社の人が動かします。
リポジトリにある設定とコードは動く例で、写して使う物ではありません。

土台は、aiseed.dev の「AIネイティブな仕事の作法 — ソフトウェア開発編」の自立編です
(https://aiseed.dev/ai-native-ways/software/ 、CC BY 4.0)。

== 誰が、どんなときに使うか

aiai の流れで、自分のアプリや Web を作れるようになった人が使います。たとえば、次のようなときです。

* 会社や団体から、システムを作ってほしいと頼まれたとき
* 会社が今どのサービスを使い、何を外に預けているかを知りたいとき
* 会社の仕事に合うシステム(会員の受付、予約、帳簿など)を作るとき

aiai tools のスキルを読めば、会社で何をしているか、何を守る必要があるかが分かります。そのうえで、
会社に合うシステムを、AI と一緒に作れます。

== 中にある物

=== 順に置き換えるスキル

自立編の順です。1 つ終わってから次に進みます。

[cols="1,2,4"]
|===
|順 |フォルダー |中身

|0 |`server` |サーバー、Docker、Caddy、DNS、バックアップ(すべての土台)
|1 |`dodai` |データの置き場(SQLite、PostgreSQL と pgvector、DuckDB、Polars)
|2 |`ninshou` |認証(PocketBase。社員は Apple ID か Google ID でサインインする)
|3 |`code` |コードの置き場(Forgejo)
|4 |`bunsho` |文書(OnlyOffice Docs)
|5 |`mail` |メール(Stalwart)
|6 |`kaigi` |会議と予約(Jitsi Meet、Cal.diy、BigBlueButton、Radicale)
|7 |`web` |Web サイトの公開(Cloudflare Pages。作り方は aiai の `website/` のスキル)
|8 |`api` |API(FastAPI。古い基幹の仕組みの置き換え)
|9 |`jouhou` |AI の前の整備(OCR、分類、Markdown や adoc への書き起こし)
|10 |`ai` |社内の AI(Ollama、AnythingLLM、pgvector で RAG)
|11 |`bunseki` |表のデータから予測する(Polars、scikit-learn、LightGBM、SHAP)
|12 |`tryton` |ERP とは何かと、Tryton を自分の PC で動かす手順。日本語の訳と日本の会計を足す
|===

=== 事業用のアプリの部品

事業用のアプリにいつも出てくる部品です。順番はなく、要る物から使います。

[cols="2,5"]
|===
|フォルダー |中身

|`kaiin` |会員を集めて預かる(招待、同意、本人が自分の記録を見て消せる)
|`tsuuchi` |通知(取引のメールと Web Push。広告は入れない)
|`renraku` |メッセージ(会社と会員のやりとり。会員どうしのときの通報とブロック)
|`honnin` |本人確認(民泊と簡易宿所の宿泊者名簿が中心)
|`kagi` |鍵(スマートロックで、期間を決めた鍵を出して消す)
|`minpaku` |民泊の受付(受付番号、名簿、承認、鍵、定期報告)
|`kanshi` |住宅と空き家の見守り(カメラと、画像を読む AI)
|`kaiseki` |アクセス解析を自分のサーバーで行う
|`network` |Linux の PC をルーターにする
|===

部品は、たとえば次のようにつながります。

* 会員制のサービス: 会員登録(`kaiin`)、サインイン(`ninshou`)、知らせ(`tsuuchi`)、問い合わせ(`renraku`)、見たページの記録(`kaiseki`)
* 民泊: 予約と受付(`minpaku`)、本人確認と宿泊者名簿(`honnin`)、鍵(`kagi`)、知らせ(`tsuuchi`)

フォルダーごとの `README.md` に、何ができるか、誰が使うか、何を決めるかを書いています。
`SKILL.md` は AI が読む物です。

== aiai との関係

aiai と aiai tools は、同じ書き方で作っています。スキルが中心であること、出典と確かめた日を
付けること、決めるのは本人であることは同じです。

aiai で、自分のアプリや Web を作れるようになったら、次に aiai tools で、会社や団体の仕事に
広げられます。Web サイトの作り方は、aiai の `website/` のスキルをそのまま使います。

== 使い始め方

. リポジトリを手元に取ります。Web サイトの作り方は aiai のスキルを使うので、aiai も取ります
+
----
git clone https://github.com/aiseed-dev/aiai-tools.git
----
. 使いたいフォルダーの `README.md` を読み、何ができるかを確かめます
. その `SKILL.md` を AI に読ませ、一緒に進めます。会社の仕組みを置き換えるときは、`server/SKILL.md` から順に進めます
. 入れた物、困ったこと、変わっていたことは、リポジトリの「報告のしかた」(`HOUKOKU.md`)のとおり、Issue で知らせます

== 守ること

* 秘密の値(API のトークンと鍵、パスワード、`.env` など)は、AI への依頼にもリポジトリにも入れません
* 社員やお客さんの個人の情報は、学習に使わないと確かめた AI のサービスか、自分の機械の AI でだけ扱います
* 使う OSS は、ライセンスを確かめてから入れます

== いまの状態とライセンス

手順と設定は、公式の説明書で確かめた物です。多くは、まだサーバーに入れて動かしていません。
動かした人の報告で直します。

ライセンスは、コードが AGPL-3.0-or-later、それ以外(文書、設定の見本)が CC BY 4.0 です。
Tryton の日本語の訳は、Tryton と同じ GPL-3.0-or-later です。
