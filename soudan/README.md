# セカンドオピニオン

自分の AI と一緒に作った転職の考え、何を学ぶかの考え、履歴書、起業の企画書を、ほかの会社の AI のモデルに
見てもらう仕組みです。主役は、本人がふだん使っている AI です。1 つの AI だけに頼らないように、
aiai のサーバーが別の目を用意します。

募集に応じた人だけが使えます。研究の係の人が招待の番号を作り、募集に応じた人に 1 つずつ渡します。
番号は、1 つにつき 1 人だけが使えます。

1. Apple か Google でサインインします(`moushikomi/` と同じ仕組みです)
2. 招待の番号を入れ、記録を残すことと、研究に使うことに同意します(`同意.md`)
3. 識別情報を除いた下書きを貼り、相談の種類と、モデルを 1 つか 2 つ選びます。2 つ選ぶと、
   答えを比べられます
4. 答えに 1 から 5 の評価を付けます
5. 応募した、面接を受けた、開業届を出した、のような出来事を、いつでも書き足します
6. 次に相談するときは、前の相談と出来事を踏まえて答えます

記録は日付順に積み重なり、どんな相談をした人がその後どう動いたか、モデルによって答えが
どう違うかを調べる材料になります。本人は、いつでも自分の記録を見られ、すべて消せます。
研究の係の人は、招待の番号を作れます(`POST /api/research/invites`)。研究の係の人が見られるのは、モデルと種類ごとの数と評価の平均だけで、下書きや答えの文は
見られません。

## 続け方

当面は、無料の研究サービスとして動かします。記録(評価と、本人が書き足す出来事)で効果を
確かめ、効果があると分かったら、低額の会費をいただいて運営します。かかる費用は、主に
AI のモデルの API の利用料です。相談ごとに、モデルに渡した量と答えた量(トークン数)を
記録しているので、1 回あたりの費用と、会費の額を、この記録から決めます。

本人が使っている AI だけで十分だと分かれば、それも研究の結果です。その場合は、この仕組みを
続ける必要はありません。AI ではなく人の助けが要ると分かれば、相談できる人を紹介する
サイトにすることも考えます。

## 確かめる観点

`観点/` に書きます。`共通.md` はすべての相談に、ほかのファイルは、ファイルの名前の種類の
相談に使います。種類を足すときは、ファイルを足すだけです。

| ファイル | 見る物 |
|---|---|
| `共通.md` | 答え方(答えを先に出さない、根拠を聞く、確かめる先を伝える、次の行動で終える) |
| `転職.md` | 長所の根拠、長所と仕事のつながり、ソフトウェアの外の仕事も考えたか |
| `学び.md` | 高校生と大学の 1 回生の、何を学ぶかの考え。長所の根拠、長所と分野のつながり、学校の資料で確かめたか |
| `履歴書.md` | 志望動機と自己 PR の根拠、年月の食い違い、書き方のそろい |
| `企画書.md` | 誰に何をいくらで、数字の元、始めるお金、届出や許可を調べたか |

## 識別情報を AI に渡さない

下書きと出来事に、メールアドレス、電話番号、郵便番号、12 桁の数字(個人番号の形)に見える
物があると、AI に送らずに戻し、何が入っていたかを伝えます。全角の数字も確かめます。
氏名や住所の文字は形で見分けられないので、画面で、除いてから貼るよう伝えます。

## 使いすぎを防ぐ

モデルを呼ぶ回数に、一人 1 日の上限(`SOUDAN_PER_DAY`、既定 10)と、全員を合わせた 1 日の
上限(`SOUDAN_DAY_LIMIT`、既定 300)があります。

## 動かす

`moushikomi/` と同じ部品(conda-forge の `fastapi`、`uvicorn`、`pyjwt`、`cryptography`、
`python-multipart`)を使います。Anthropic のモデルを使うときは、`anthropic` も要ります。

```
python soudan/test_server.py
```

偽の Apple と Google(`moushikomi/fake_id.py`)と、偽のモデル 2 つを相手に、サインインから
記録を消すまでを確かめます。画面も一緒に試すときは、`python site/try.py` です(`site/README.md`)。

設定は、環境の変数で渡します。サインインの設定(`BASE_URL`、`RETURN_URLS`、`GOOGLE_*`、
`APPLE_*`)は `moushikomi/` と同じです。

| 変数 | 中身 |
|---|---|
| `SOUDAN_MODELS` | 使うモデル。`会社:モデル` を空白で区切ります(例: `anthropic:claude-opus-5-5`) |
| `ANTHROPIC_API_KEY` | Anthropic のモデルの API キー |
| `SOUDAN_PER_DAY`、`SOUDAN_DAY_LIMIT` | 上の上限 |
| `RESEARCH_EMAILS` | 研究の係の人(招待の番号を作り、まとめを見る人)のサインインのメールアドレス |
| `DB` | データベースのファイル(既定は `soudan/soudan.db`) |

`soudan.db` には、お客さんのメールアドレスと相談の中身が入ります。リポジトリに入れません。
