# Office と基幹システムの断絶を、AI でつなぐ

書類をデータで持てば、つなぐ仕事は、仕事を知っている人の手に戻る

私は 1990 年代の前半に、県で財務会計システムの開発を担当しました。当時はバッチで運用していた時代で、
仕事の流れを変える必要があったので、発注する側にも仕事がたくさんありました。

その時から、ずっと問題だと思ってきたことがあります。日常の業務に使う Office ソフトと、基幹システムとの
断絶です。

## 断絶とは

基幹システムには、決まった形のデータが入ります。財務会計なら、予算、支出、決算の数字です。

一方で、日常の仕事は Office ソフトで回ります。起案の文書、説明の資料、集計の表、照会への回答。
多くは Word と Excel で作ります。

この 2 つは、つながっていません。間を埋めるのは、人の手です。

- 基幹システムから出した数字を、Excel に打ち直す
- Excel で作った表を見ながら、基幹システムに入れ直す
- 同じ数字や名前を、書類ごとに何度も書く

Office の書類は、印刷したときの見た目で作られています。表の中の数字が何を表しているかは、作った人に
しか分かりません。プログラムからは読めないので、つなぐには人が読んで、打ち直すしかありません。

## 公開用の Web も、業務用のアプリも

公開用の Web も、同じく断絶しています。基幹システムの数字や、Office で作った書類の中身を Web に
載せるとき、もう一度打ち直すか、PDF にして貼ります。載った物は、人には読めても、プログラムや AI には
読みにくい形です。

業務用のアプリも、ほとんどが Web になりました。でも、画面がブラウザーに移っただけで、つながっては
いません。ある画面から CSV を書き出し、Excel で整えて、別の画面に入れ直します。断絶の場所が
変わっただけです。

## なぜ、30 年続いたのか

基幹システムは、業者に委託して作るのが普通でした。日々の書類の作りまでは、手が届きませんでした。
Office と基幹システムをつなぐプログラムを書くには、費用と人が要りました。

Office の側は、書類の見た目を作る道具として広まりました。データを持つ道具ではありません。書類は
docx と xlsx の中に入り、中の数字をほかのプログラムが使うのは難しくなりました。書類を作るにも読むにも
同じソフトに頼る形になり、これが囲い込みになりました。

最近は、SaaS を入れたら終わりと考える人が多いようです。でも、SaaS を入れても、断絶は消えません。
Office と SaaS の間に移るだけです。

## AI で、つなげる時代になった

AI が得意なのは、コーディングです。つなぐプログラム、つまり基幹システムから出したデータを読み、
書類に写し、数が合っているかを確かめるプログラムを、安く書けます。

ただし、AI が読めるのは、データとして書かれた物です。見た目のための書類は、AI にも読みにくい。
だから、書類のデータを、文字だけのファイルで持ちます。aiai では、adoc という形で書き、印刷するときだけ
PDF にします。

aiai では、次のようにしています。

- **1 つのデータから、書類を作る。** 開業届と青色申告承認申請書では、事業の事実を 1 つのデータ
  (`事業.sheet.adoc`)に書きます。書類ごとのデータは、プログラム(`tools/todoke.py`)が写します。
  受け取る側も、同じプログラムで確かめられます。同じことを 2 度書きません
- **Office の書類は、Office なしで読み書きする。** OSS の文書と表計算の officework は、書類を adoc、
  表を `.sheet.adoc` で持ち、docx と xlsx は受け渡しのときに読み書きします。表のセルから、Python の
  関数を呼べます
- **公開用の Web も、同じデータから作る。** 事業の Web サイトは、届出と同じデータから、公開してよい
  事実だけを写して、静的なページにします。人が検索ではなく AI に聞くようになると、AI が読める確かな
  中身が力になります
- **基幹システムは、置き換えずにつなぐ。** 会社や団体には、今の基幹システムをいきなり置き換えず、
  データを CSV で写して見ることと、周りの仕事から入ります。ERP は、1 つの出来事を 1 度だけ入れ、
  次の書類はそこから作る仕組みです。日々の書類も、同じ考えでつなげます

## 画面は、Flet で作る

業務用のアプリの画面は、ほとんどが Web です。Web の画面は、JavaScript か、それに型を付けた TypeScript で
書きます。一方で、データを扱う所や AI を呼ぶ所は、Python で書くことが多くあります。画面と中身で、言語が
2 つに分かれます。ここにも断絶があります。

aiai と、天気のアプリ(AIseed Weather。気象のデータから天気図を作るツール)は、画面を Flet で作って
います。Flet は、Python で、Web、PC、スマートフォンのアプリを作る OSS です(Apache-2.0)。画面も中身も、
同じ Python で書けます。

Flet の機能は、まだ十分ではありません。でも、OSS で、Flutter の部品を包んだ拡張を作れるので、足りない
所は AI と一緒に補えます。天気のアプリの例です。

- **足りない部品を作った。** 気象の格子データを GPU で描く部品が無かったので、AI と一緒に Flet の拡張
  (flet-gpufield)を作りました。拡大、移動、風の粒子、等値線を部品の中で扱い、Linux の内蔵 GPU で、
  1 秒に 57〜59 コマで描けます。ほかのアプリでも使えるように、MIT で公開しています
- **不具合を見つけて、補った。** Flet 1.0.4 の `use_effect` には、後始末が一度も呼ばれない書き方が
  ありました。天気のアプリでは、再生が止まらず、だんだん速くなる不具合として出ました。AI が原因を
  見つけ、必ず後始末を呼ぶ部品(`use_task_effect`)を作りました。同じ書き方が戻ったら失敗する試験と、
  AI への決まり(スキル)にも書きました

TypeScript には、次の欠陥があります。

- **型は、動かす前に消える。** TypeScript の説明書にも、型の注釈はプログラムの動きを決して変えない、と
  あります。外から来たデータ(基幹システムの CSV、ほかの Web の答え)が型のとおりかは、動いている間は
  確かめられません。断絶の境目こそ、確かめが要る所です
- **型の仕組みは、わざと完全にしていない。** 説明書は、コンパイルのときに安全と分からない操作も通す
  所があり、型の仕組みが健全(sound)ではない、と書いています
- **同じデータの型を、2 度書く。** 中身を Python で書くと、同じデータの型を TypeScript でも書くことに
  なります。片方を直したら、もう片方も直さないといけません。言語の間に、新しい断絶ができます
- **部品の山に頼る。** 画面のためだけに、npm の部品をたくさん入れます。その部品が攻撃の的になります。
  2025 年 9 月には、自分で広がる「Shai-Hulud」という仕組みに、npm の 500 を超える部品が乗っ取られ、
  開発者の GitHub やクラウドの鍵が盗まれました

(TypeScript「The Basics」の Erased Types、https://www.typescriptlang.org/docs/handbook/2/basic-types.html 。
「Type Compatibility」の A Note on Soundness、https://www.typescriptlang.org/docs/handbook/type-compatibility.html 。

## つなぐのは、仕事を知っている人

断絶を埋めてきたのは、現場の人の手作業でした。どの数字を、どこから、どの書類に写すのか。それを
知っているのは、その仕事をしている人です。

AI はコーディングは得意ですが、その職場で何をしているかは知りません。少し言われると、すぐに方針を
変えます。何をつなぐかは、仕事を知っている人が決めます。

1990 年代は、仕事の流れを変えるために、発注する側にも仕事がありました。いまは、業者に委託する
代わりに、仕事を知っている人が、AI につなぐプログラムを書かせられます。30 年続いた断絶を埋める
仕事は、外の業者ではなく、仕事を知っている人の手に戻ってきました。

## まとめ

- 日常の業務に使う Office ソフトと基幹システムは、30 年、つながってこなかった。間は人の手が埋めた。
  公開用の Web も、Web になった業務用のアプリも、同じく断絶している
- 原因は、書類が見た目で作られ、データとして読めなかったこと。つなぐプログラムに費用と人が要ったこと
- いまは、AI がつなぐプログラムを安く書ける。そのために、書類のデータを文字のファイルで持つ
- 画面は Flet で、中身と同じ Python で書く。足りない機能は、AI と一緒に補える。TypeScript は、型が
  動かす前に消え、言語が 2 つに分かれて、新しい断絶を作る
- 何をつなぐかを決めるのは、仕事を知っている人。それが、AI の時代の、ラスト 1 マイルの仕事です
